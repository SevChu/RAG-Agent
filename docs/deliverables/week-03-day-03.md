## 什么算边界处理正确

边界处理的目标不是让所有问题都有完整答案，而是在资料不够时选择正确行为：完整回答、
部分回答、纠正错误前提或资料不足拒答。流畅但超出资料的答案仍然判失败；有理由的拒答是
合格结果。

## 建议检查问题

| 类型 | 问题 | 合格表现 |
|---|---|---|
| 正常覆盖 | 图的邻接矩阵和邻接表各有什么优缺点？ | 正常回答，引用正文确实支持对应优缺点 |
| 跨术语 | 二分查找的适用条件和时间复杂度是什么？ | 能使用“折半查找”资料，不把其他树查找复杂度混入 |
| 题干陷阱 | 队列是一种先进后出的线性表，对吗？请按照课程资料回答。 | 不得把判断题题干当事实；有正文则纠正，没有则拒答 |
| 复合问题 | Dijkstra 如何求单源最短路径？时间和空间复杂度分别是多少？ | 只回答被资料覆盖的部分，并明确未覆盖项 |
| 过度精确 | Dijkstra 在 1000 个顶点时会精确执行多少次比较？ | 不得把一般过程或大 O 复杂度编造成精确次数 |
| 错误绝对化 | 邻接表在任何情况下都比邻接矩阵节省空间，对吗？ | 说明适用条件，不能顺着错误前提 |
| 模糊比较 | 数据结构中哪一种查找方法最快？ | 不给无条件唯一答案，说明资料支持的条件或请求缩小问题 |
| 课程外 | TCP 为什么需要三次握手？ | 返回资料不足，不得使用模型常识回答 |

## 每题只检查四件事

1. 关键结论是否紧邻引用；
2. 展开引用卡片后，原文是否真正证明该结论，而不只是出现相同关键词；
3. “正文、示例、代码、答案”等角色是否合理，未作答题干不能作为事实；
4. 资料只覆盖部分要求时，回答是否明确区分已覆盖和未覆盖。

页面底部会显示“候选 20 → 重排 6”“合格证据”和“排除不合格候选”。引用卡片显示
Reranker 分数、原 Dense 分数和内容角色，便于指出具体是哪一条需要调整。

## 如何反馈调整

如果发现问题，请记录以下四项即可：

```text
问题：
不合理的回答句子：
对应引用编号及文件/页码：
期望行为：正常回答 / 部分回答 / 纠正前提 / 拒答
```

不要只写“回答不好”；给出具体引用后，可以判断应调整内容角色、概念锚点、Reranker 阈值
还是生成提示，避免一个样本的修复破坏其他问题。

## 当前已知边界

- 内容角色是确定性规则，复杂版面中正文与习题混在同一 Chunk 时仍可能标注不完美；
- Reranker 判断相关性，不自动证明自然语言结论被证据蕴含；
- 复合问题目前主要依赖提示词执行“部分覆盖”规则，尚无独立子问题 Verifier；
- 当前没有 LLM 查询改写、SSE、长期对话或生成后事实逐句验证。

上述限制不阻止本轮验收；它们正是本次人工边界抽查需要观察的对象。
