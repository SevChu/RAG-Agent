# 第 3 周计划日 5 验收说明

## 验收目标

本次验收覆盖四类能力：课程多轮指代改写、课程助手 SSE 与中断、快速对话、两类历史隔离。
本日仍是封闭课程 RAG，不验收外部资料搜索或 `[课n]` / `[外n]` 混合引用。

## 启动方式

后端：

```powershell
cd D:\Agentic\backend
.venv\Scripts\fastapi.exe dev app\main.py --host 127.0.0.1 --port 8000
```

前端：

```powershell
cd D:\Agentic\frontend
npm.cmd run dev -- --host 127.0.0.1
```

打开 `http://127.0.0.1:5173/assistant`。开始前确认 8000 和 5173 各只有一套服务；如果重复
启动后端，先关闭旧窗口，不要让两套 FastAPI 同时监听 8000。

## 建议验收步骤

### 1. 课程多轮指代与改写

1. 在“课程学习助手”选择“数据结构”，新建课程对话；
2. 提问：“什么是二叉搜索树？”并等待完成；
3. 继续追问：“它最坏情况下的查找复杂度是多少？”；
4. 查看第二条回答底部的“已改写检索”信息和上下文消息数；
5. 主动换题：“什么是栈？”；随后追问：“它遵循什么原则？”。

通过标准：第二问的独立检索查询明确指向二叉搜索树，第四问明确指向栈；每次回答仍有课程
引用，不能把历史助手回答当成引用。上下文消息数不超过 6，换题后不能继续错误沿用旧对象。

### 2. 新会话与课程隔离

1. 点击“新建课程对话”；
2. 不提供先行对象，直接提问：“它最坏情况下的查找复杂度是多少？”；
3. 如有另一门课程，可切换课程后检查页面是否退出原会话，再从侧栏返回原记录。

通过标准：新会话的上下文数为 0，不得继承上一会话的“二叉搜索树”；切换课程不会把原课程
消息显示或注入新课程，返回原侧栏记录后原内容仍完整。

### 3. 课程助手 SSE 与中断

1. 提交任意资料覆盖充分的问题；
2. 确认等待阶段显示“正在改写问题、召回并校验证据”，正文随后增量出现；
3. 再提交一个问题，在生成过程中点击“停止生成”；
4. 刷新页面，并从“学习助手对话”重新进入该会话。

通过标准：请求中显示“停止生成”；正常回答最终出现引用并可刷新恢复；中断片段明确显示
“已中断 · 未保存”，刷新后不得伪装成一条完整助手回答。超时或模型错误应显示具体错误，页面
不能一直停在加载状态。

### 4. 快速对话与有限上下文

1. 点击侧栏“新建快速对话”；
2. 选择 `deepseek-v4-flash` 或 `deepseek-v4-pro`；
3. 提问：“请记住本次对话代号是 DS5。”；
4. 追问：“我刚才给出的代号是什么？”；
5. 刷新页面，并从“最近对话”重新进入记录。

通过标准：输入框和发送按钮可用，回答采用 SSE 增量显示；第二问能使用当前快速会话的有限
上下文；刷新后两轮消息与实际模型仍可恢复。快速对话回答不显示课程引用，也不声称来自课程
知识库。

### 5. 双历史隔离与删除

1. 查看侧栏“最近对话”和“学习助手对话”；
2. 分别进入刚才的快速对话和课程对话；
3. 各删除一条专门用于验收的测试会话。

通过标准：快速对话只出现在“最近对话”，课程对话只出现在“学习助手对话”；进入记录时路由
和内容类型正确；删除只移除目标会话及消息，不影响课程、资料、向量索引或另一类历史。

### 6. 资料不足与历史污染回归

1. 在数据结构课程新建对话，提问：“TCP 三次握手的状态转移是什么？”；
2. 在已有正确课程回答之后再提出同一问题。

通过标准：两种情况下都执行当前课程检索并在证据不足时拒答；不能因为历史中存在模型回答而
绕过证据门，也不能产生无课程来源的事实性答案。

## 整体通过标准

- 指代追问使用当前会话的有限历史正确改写，新会话、不同课程和快速对话之间没有上下文串扰；
- 课程检索使用改写查询，最终回答仍面向原始追问并保持引用一致、证据门和资料不足拒答；
- SSE 至少包含开始、文本增量、完成或错误，课程流另有引用事件；中断片段不保存为完整回答；
- 快速对话支持真实发送、模型选择、SSE、恢复与删除，但不检索课程资料；
- 两类侧栏历史严格分区，刷新或重启后已完成记录可恢复；
- 页面没有 API Key 暴露，后端模型白名单、课程绑定和删除边界继续有效。
