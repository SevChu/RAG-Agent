## 你的验收重点

### 回答正确性

- 回答是否直接回应问题；
- 是否出现课程资料没有提供的具体事实；
- 复合问题若证据只覆盖一部分，是否坦率说明缺少的部分；
- 资料外问题是否明确返回“资料不足”，而不是依赖模型常识作答。

### 引用正确性

- 每个重要结论后是否有引用编号；
- 编号是否都能在下方找到对应引用卡片；
- 原文是否真的支持相邻结论，而不只是主题相似；
- 文件名和页码、幻灯片号或文本行号是否正确；
- 练习题题干是否被错误当成正确结论。

### 回答风格

- “简洁”是否为无标题单段或最多 3 个短要点，并明显短于“均衡”；
- “均衡”是否出现“结论、关键要点”结构以及 2～4 个实质要点；
- “详细”是否出现“资料依据、推导与延伸、边界与易错点”结构；
- 详细模式是否给出 2～4 条“基于资料的推导”，而不是简单重复原文；
- 每条推导是否能从所引资料前提推出，且没有夹带资料外算法细节、数值或例子；
- 三种风格是否都保持相同的事实边界和引用要求。

## 首轮反馈后的复测方法

请直接复用首轮测试中同一个问题，依次选择简洁、均衡、详细。相同问题和相同资料范围能
避免检索内容差异干扰风格判断。预期差异如下：

| 风格 | 预期表现 |
|---|---|
| 简洁 | 直接结论，单段或最多 3 个短要点，无独立推导 |
| 均衡 | 结论后有 2～4 个关键要点，必要时说明适用边界 |
| 详细 | 解释资料依据，并增加 2～4 条证据锚定推导和易错点 |

详细模式中的推导应明确标为“基于资料的推导”。如果只是换一种说法复述原文，或推导中
出现资料没有提供的新事实，均视为仍未通过。

## 引用清单不一致错误修复

首轮复测曾出现：

```text
模型回答中的引用与引用清单不一致，本次回答已拦截，请重试。
```

原因不是资料或 API Key，而是模型正文引用顺序与 JSON 来源清单顺序可能不同；例如正文
先使用 `[2]` 再使用 `[1]`，清单却按编号返回 `[1, 2]`。模型也可能把两条来源写成
`[1, 2]`，而旧逻辑只识别单个 `[1]`。

现已改为以正文中实际可见的引用为准，支持：

- 单条引用 `[1]`；
- 半角逗号组合 `[1, 2]`；
- 中文逗号组合 `[1，2]`；
- 顿号组合 `[1、2]`；
- 正文重复引用和正文顺序与来源清单顺序不同。

服务端会按正文首次出现顺序自动去重并生成引用卡片。正文引用不存在的编号或回答完全没有
引用时仍会拦截，因此没有降低引用真实性要求。
