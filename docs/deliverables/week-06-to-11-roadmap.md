# 第 6～11 周研发路线与 GitHub 版本节点

## 路线定位

项目暂不进入最终交付与答辩阶段。原第 6 周计划日 4～5 的 Docker、演示材料、发布候选和最终
验收整体后移到“最终交付周”；第 6～11 周依次推进评分算法、AgentProfile、微调平台、首次真实
微调、动态长上下文、资料空间记忆和自有金标集基础。每周仍保留自动测试、数据隔离和可复现性检查，不能把质量门一起后移。

当前远端 `main` 与唯一 Tag `v1.0.0` 均指向基础功能发布提交。第五周新增的 FiQA、RAGTruth、
RAGBench、统一 Dataset Adapter 和 baseline profile 1.0.0 尚未形成新的 GitHub 版本，因此将其
随本次发布形成 `v1.1.0`。

## 版本策略

- 遵循 Semantic Versioning；兼容新增使用 minor，修复使用 patch，破坏 API/数据库兼容才使用 major。
- 计划版本不等于已经发布；只有完成验收、全量回归、隐私检查、版本元数据同步并获得用户批准后，
  才创建提交、Tag、推送和 GitHub Release。
- 已发布 Tag 不移动、不覆盖；候选阶段发现问题时继续修复，不重写旧 Tag。
- 公开仓库只包含代码、配置模板、哈希和汇总指标，不上传公开数据集副本、资料空间、对话、数据库、
  模型权重、训练样本、预测明细或 API Key。
- 预发布训练平台使用 `-beta.N`；真实训练闭环通过后再发布同一 minor 的稳定版。

## 第 6 周：评分与检索算法优化（目标 `v1.2.0`）

### 计划日 1：实验注册与错误切片

- 建立候选实验登记：假设、唯一主要变量、数据/模型 revision、随机种子、主指标和守门指标；
- 统一 per-domain、正负类、长度、证据数量和错误类型切片；
- 所有优化只读取 train/validation，不重新利用 test 调参。

### 计划日 2：Dense Top-100 直接重排

- 使用现有 BGE-M3 Dense Top-100 和现有 BGE Reranker；
- 与 Dense、等权 RRF、RRF+Reranker 使用相同 FiQA 协议；
- 守门条件：Recall@100 不低于 Dense 1.1.0，单列 nDCG@10、MRR、延迟和显存。

### 计划日 3：Completeness 评分改进

- 先尝试 relevant → utilized → completeness 两阶段建模；
- 再比较线性、树模型或校准，不在同一实验同时更换特征和模型；
- 主要指标为 RAGBench validation Completeness Spearman/RMSE，其他三项不得显著退化。

### 计划日 4：NLI 幻觉定位

- 先审查适合句子级 entailment/contradiction 的开源模型、许可、大小和显存；
- 新模型下载前单独提交审批；
- 在 RAGTruth validation 上比较 AUPRC、回答级 Recall 和 span char F1。

### 计划日 5：冻结 1.2.0 候选

- 汇总质量、时延、资源、稳定性和分域结果；
- 仅冻结通过 validation 晋级门的候选；
- 用户批准后才执行一次最终 test，并决定是否创建 `v1.2.0`。

## 第 7 周：AgentProfile 与多智能体基础（目标 `v1.3.0`）

1. 设计 AgentProfile、AgentProfileRevision 和会话绑定关系，提供 Alembic 迁移；
2. 实现创建、复制、修改、停用、版本查看和兼容读取 API；
3. 配置系统提示、供应商/模型、资料空间范围、工具权限、上下文策略、检索和评分 profile；
4. 执行链路按会话绑定的 revision 运行，不能被后续配置覆盖；
5. 实现智能体列表与编辑界面，完成空间隔离、历史会话和模型路由回归。

第 7 周只提供配置和版本基础，不伪装成已实现模型训练。

## 第 8 周：微调平台基础（目标 `v1.4.0-beta.1`）

1. 建立 TrainingDataset Registry，记录来源、许可、PII、去重、split、哈希和审核状态；
2. 建立训练任务状态机、日志、进度、取消、失败恢复和资源估算；
3. 建立 Adapter Registry，记录 base model、数据、参数、代码、指标和回滚关系；
4. 实现选择 AgentProfile、数据、训练目标和 LoRA/QLoRA 参数的五步界面；
5. 使用 Fake Trainer 跑通端到端，不安装或下载真实训练模型即发布 beta 候选。

开始本周前需要确定原生 Windows 或 WSL2/Linux 训练环境；新增 Transformers、PEFT、TRL、
bitsandbytes 等依赖需单独审批。

## 第 9 周：首次真实微调（目标 `v1.4.0`）

1. 优先选择小型 Scorer 或 Reranker，不直接以生成大模型 LoRA 作为第一轮；
2. 审批 base model、许可、下载大小、训练数据、显存/时间和外部成本；
3. 固定未微调 base model 对照，只在 train/validation 调参；
4. 将训练产物登记为 Adapter，比较质量、稳定性、时延、显存和回滚；
5. 用户批准后执行一次 test，将通过的 Adapter 绑定到指定 AgentProfile，但不自动设为全局默认。

生成模型逐智能体 LoRA/QLoRA 等自有训练数据与目标稳定后再进入后续 minor 版本。

## 第 10 周：动态长上下文与资料空间记忆（目标 `v1.5.0`）

### 计划日 1：上下文能力与基线

- 将旧“课程记忆”设计迁移为通用资料空间语义；
- 建立当前 6 条/6000 字符基线和模型上下文能力表；
- 固定 M0/M1/M2 对照、Token、延迟、长程指代和空间泄漏指标。

### 计划日 2：动态 Token 预算与历史选择

- 按模型窗口、系统指令、当前问题、检索证据、输出预留和安全余量分配历史预算；
- 优先保留最近原文，较早历史使用滚动摘要与相关片段；
- 未知模型或估算异常时保守降级，不直接向用户暴露上游 context-length 错误。

### 计划日 3：资料空间记忆后端

- 新增记忆实体、来源、状态、重要性、替换关系和生命周期迁移；
- 支持候选、确认、编辑、停用、删除和全部清空；
- 记忆只允许绑定一个资料空间，不作为资料事实引用。

### 计划日 4：记忆读取与安全边界

- 查询同时验证资料空间归属，并限制条数和独立 Token 预算；
- 快速对话、其他资料空间和外部网页不得自动写入；
- 提取或读取失败时降级为无记忆模式，不阻断普通 RAG。

### 计划日 5：前端控制与隔离验收

- 增加记忆开关、列表、来源、编辑、删除和清空入口；
- 报告本次使用条数而不暴露内部提示；
- 跨空间泄漏、停用后使用、删除后使用的容忍值均为 0。

## 第 11 周：自有人工金标集基础（目标 `v1.5.0`）

### 计划日 1：标注规范与 50 条校准集

- 冻结 query、资料快照、answerability、evidence sufficiency、reference answer、引用、拒答、
  hallucination span 和 TRACe 标签契约；
- 用 50 条校准 Case 发现歧义并修订指南，不作为训练或最终测试数据。

### 计划日 2：标注与复核工具

- 实现双人独立标注、冲突提示、仲裁、版本记录和可恢复导入导出；
- Sealed Test 在训练数据选择器中不可见；
- 导出前扫描 PII、密钥、内部路径和版权限制。

### 计划日 3：首批 200 条 Pilot

- 覆盖中文资料问答、跨文档、数字/表格、长上下文、相似概念、资料不足和正确/错误拒答；
- 按来源文档分组切分，避免改写问题跨 split；
- 200 条目标依赖实际人工标注进度，工具完成不等同于标签已经合格。

### 计划日 4：质量门与数据版本

- 分类标签报告一致性系数，连续标签报告相关性/绝对误差，span 报告 overlap；
- 完成去重、污染、许可、PII、manifest、schema version 和 split hash；
- 未通过双人复核与仲裁的 Case 不得进入 Gold 版本。

### 计划日 5：联合报告与 1.5.0 候选

- 联合公开 Benchmark、AgentProfile/Adapter、长上下文/记忆和私有 Pilot 的脱敏汇总；
- 冻结标注工具、Schema 和评测协议，原始样本继续留在 Git 忽略目录；
- Development 800 条和 Sealed Test 1,000 条作为后续数据版本持续建设，不虚报为一周完成；
- 完成前后端、迁移、隐私与隔离门后，交由用户决定是否发布 `v1.5.0`。

## 最终交付

- Docker、全新环境安装、演示脚本、答辩材料和最终交付验收移到实际交付周；
- GitHub Release 页面可在每个已批准版本创建，不需要等待最终答辩；
- 每个计划版本仍需保留测试、迁移、隐私、安全、数据许可和 Git 忽略检查。

## 每个 GitHub 版本的固定发布门

1. 用户明确验收本节点并批准提交/推送；
2. 后端测试、Ruff、Mypy 和前端测试、类型、Lint、构建通过；
3. 数据库迁移、OpenAPI、关键浏览器路径和向后兼容验证通过；
4. 数据、模型、缓存、预测、资料、对话、数据库和 Key 均未进入 Git；
5. `backend/pyproject.toml`、`backend/uv.lock`、FastAPI、前端 package/lock、CHANGELOG 同步；
6. Release Notes 记录功能、实验结果、数据/模型身份、限制和升级方式；
7. 创建不可变 annotated Tag，并在用户批准后推送 GitHub。
