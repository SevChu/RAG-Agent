# 第 5 周实施计划：通用智能体迁移与公开 Benchmark 基线

## 本周目标

第五周调整项目定位：系统不再以“计算机课程学习助手”作为唯一产品形态，而是演进为支持多个
资料空间、可配置智能体、可复现实验和后续逐智能体微调的通用 Agent 平台。

本周不删除已经完成的课程问答、总结和组卷能力，而是将它们降级为通用智能体可选择的能力模板。
原第 5 周已经完成的 100 条本地候选评测集和可恢复执行器继续保留为工程资产，但不再充当唯一
基准。公开数据集在用户逐项审批前只做来源、许可、规模和接入方案审查，不下载、不安装。

本周完成标准：

- 完成产品语义从“课程学习”到“通用智能体 + 资料空间”的第一阶段迁移；
- 建立统一 Benchmark Dataset Adapter 和版本清单；
- 在获批的公开数据集上冻结经典检索与回答评分基线；
- 将被测系统指标与评分器自身质量指标分开；
- 输出可复现的配置、数据版本、指标、延迟、成本和实验结论；
- 为下一阶段多智能体配置、长上下文、空间记忆和逐智能体微调保留稳定接口。

详细产品边界见[通用智能体平台迁移设计决策](../design-decisions/general-agent-platform.md)。

## 计划日 1：产品定位与界面语义迁移

### 实施内容

- 将品牌与用户可见概念调整为 `Agentic`、资料空间、空间资料和智能体对话；
- 将资料问答、资料总结、内容生成保留为通用智能体能力；
- 更新 README、第五周计划、工程日志和迁移设计决策；
- 前端完成第一阶段文案、导航、空状态、确认框和无障碍标签迁移；
- 暂时保留 `Course`、`course_id`、`/courses`、现有数据库表和组件文件名；
- 明确后续 `AgentProfile`、`ResourceSpace`、评测套件和微调版本的领域模型。

### 验收

- 用户主路径不再把系统描述为只服务课程学习；
- 侧边栏展示“智能体对话”和“资料空间”；
- 创建、进入、删除资料空间及空间内资料管理文案一致；
- 快速对话明确不使用资料空间知识库；
- 前后端既有功能和自动化回归不受影响；
- 本日不下载公开数据、不调用外部模型、不修改数据库结构。

## 计划日 2：公开数据契约与 Benchmark Adapter

### 实施内容

- 定义统一数据契约：dataset、corpus、query、reference answer、qrels、response 和细粒度标签；
- 增加数据集注册表，记录来源、版本、许可、哈希、split、语言、领域和本地状态；
- 建立 `candidate → approved → downloaded → verified → frozen` 状态机；
- 用户审批后优先接入 BEIR SciFact，其他数据仍分别审批；
- 将现有 100 条本地数据注册为 `local-candidate`，不与公开 test split 混用；
- 下载后校验哈希并保存不可变清单。

### 验收

- 未下载数据时也可以校验注册表和许可元数据；
- 适配器能输出统一的 corpus/query/qrels 或 question/context/response/label 结构；
- train、validation、test 用途固定，测试集不参与参数和阈值选择；
- 未经用户逐项批准不会访问数据下载端点。

## 计划日 3：经典检索基线

### 实施内容

- 在获批的完整语料和 qrels 上运行 BM25；
- 运行当前 BGE-M3 Dense、融合检索和 BGE Reranker 基线；
- 固定分块、Top-K、随机种子、模型版本和硬件信息；
- 输出 Recall@K、Precision@K、MRR、MAP、nDCG、延迟和资源占用。

### 验收

- 每个实验只改变一个主要变量；
- 检索结果可保存为标准 run 文件并可重复评分；
- 公开 qrels 与项目内部资料空间数据严格隔离；
- 不用生成模型指标掩盖检索失败。

## 计划日 4：经典回答评分器基线

### 实施内容

- 建立 Exact Match、Token F1、ROUGE-L 和 BERTScore 确定性基线；
- 建立 RAGAS Faithfulness、Answer Relevancy、Context Precision/Recall 基线；
- 建立 RAG Triad 或等价的上下文相关性、忠实性、答案相关性基线；
- 在 RAGBench 上验证相关性、利用率、完整性和忠实性；
- 在 RAGTruth 上验证回答级和细粒度幻觉检测；
- 记录 Judge 模型、提示版本、重复运行方差、token、延迟和失败样本。

### 验收

- 评分器输出与被测 Agent 输出分开持久化；
- 分类评分器报告 Precision、Recall、F1、AUROC 和 AUPRC；
- 连续评分器报告 Pearson、Spearman、校准误差和重复运行稳定性；
- 不能以 LLM-as-Judge 分数直接代替公开标注或人工审核。

## 计划日 5：基线报告与后续研究入口

### 实施内容

- 汇总经典检索与回答评分算法 benchmark；
- 分析检索遗漏、噪声、拒答、证据不足、幻觉和评分器误判；
- 冻结推荐默认参数和评分器版本；
- 形成自研评分算法的改进假设，不使用 test split 调参；
- 输出多智能体、长上下文、资料空间记忆和逐智能体微调界面的后续里程碑；
- 制定最终自有人工金标测试集的渐进建设方案。

### 验收

- 所有结果可追溯到数据哈希、代码提交、配置和模型版本；
- 经典基线与后续自研方案使用相同测试协议；
- 报告同时包含质量、成本、延迟、稳定性和已知限制；
- 用户可以据此批准进入评分算法优化或微调平台建设。

## 后续阶段

1. `AgentProfile` 与多智能体创建、配置、版本化；
2. 动态长上下文和仅限资料空间的长期记忆；
3. 每个智能体的 LoRA/QLoRA 微调界面、训练任务和 Adapter 注册表；
4. 经典评分器基础上的融合、校准和小模型微调；
5. 最终自有人工金标数据集与公开 Benchmark 的联合报告。

## 数据下载审批边界

当前仅将 BEIR SciFact、RGB refined、RAGBench 代表性子集、RAGTruth test split 和 IBM MTRAG
列为候选，不视为用户已批准下载。每项下载前必须再次提交来源、许可、预计大小、保存目录、
下载命令和校验方式，并取得用户明确批准。
