## 建议验收用例

建议先使用资料覆盖较完整的课程和章节，依次新建对话发送以下请求。章节号和概念名可以替换为
你实际教材中的内容：

1. `总结第三章。`
2. `只总结第三章最值得考前复习的内容，按优先级列出，不要写通用学习建议。`
3. `对比总结栈和队列最容易混淆的条件、操作端点和适用场景。`
4. `从 C++ 实现角度总结二叉树遍历，重点说明函数结构和容易写错的边界。`
5. `把快速排序总结成从输入到递归结束的流程，不要展开考试建议。`
6. `只用反例和错误做法总结指针这一章，不要重复概念定义。`
7. `总结第三章和第五章之间的前置关系，说明学习顺序。`
8. `从“工程取舍与可维护性”的角度总结哈希表。`
9. `同时总结图遍历的算法流程、复杂度来源和 C++ 实现检查清单。`
10. `总结动态规划，但排除公式和代码，只解释状态设计与转移思路。`

第 1 条用于验收模糊请求的稳定综合回退；第 2～10 条用于验收明确方向、未预注册方向、组合
约束和排除约束。若课程资料没有某类证据，正确结果应在对应章节显示具体资料限制，而不是使用
模型常识补齐。

## 通过标准

- 第 1 条显示“综合总结计划”，多次请求保持稳定的综合结构；
- 第 2～10 条显示“动态总结计划”，标题、章节数量、组织方式和重点随请求实质变化，不再统一
  输出固定八段；
- 状态卡中的目标与原请求一致，章节数量与正文二级标题基本对应；
- 明确要求的方向出现在对应正文中，明确排除的内容没有被通用模板补回；
- 每个事实性结论使用有效 `[课n]`，引用卡能打开并指向当前课程资料；不出现 `[外n]` 或 `[n]`；
- 总结始终显示仅课程资料，外部搜索没有触发；
- 某节证据不足时局部显示“资料限制”，其他有证据章节仍可正常生成；
- 重新打开该对话后，正文、引用、动态计划与质量诊断仍能恢复；此前计划日 3 创建的旧总结
  对话也能正常打开。

如出现模型结构化输出异常，系统应明确拦截并提示重试，不能保存为一份已通过质量校验的总结。

### 首轮验收修复说明

首轮发送 `总结第三章` 时曾返回“边界与易错点使用了未分配给该节的证据”。原因是服务端把
各章节独立检索得到的编号误当成了硬授权边界；该引用实际仍是同一第三章范围内、已通过安全门
的课程证据。现已改为：分节编号只表示优先证据，同一总结范围内的有效课程证据允许跨节复用，
并写入 `cross_section_evidence_reuse` 诊断。`[外n]`、`[n]`、越界编号和范围外证据仍会拦截。
对应的单元和 API 回归用例已加入全量测试。

### 第二轮验收修复说明

测试 `从 C++ 实现角度总结二叉树遍历，重点说明函数结构和容易写错的边界。` 时，曾返回
“正文引用与声明不一致”。其中正文 `[课n]` 是真实输出依据，而模型生成的 `used_source_ids`
只是可从正文推导的重复声明。现已由服务端从正文重新计算并覆盖该字段，同时用 Planner 归一化
章节标题和目的；校正结果写入 `normalized_source_declarations` 和
`normalized_section_metadata`。正文中的外部、含糊或越界引用仍然硬拦截。已加入使用相同原句
及“容易写错的边界条件汇总”章节的 API 回归用例。
