## 建议验收步骤

### 1. 模型切换

1. 进入“设置”，确认模型下拉框不再禁用，包含 `deepseek-v4-flash` 和
   `deepseek-v4-pro`；
2. 选择 `deepseek-v4-pro`，回到“课程学习助手”；
3. 确认“生成模型”和“本次请求模型”均显示 `deepseek-v4-pro`；
4. 提问一个资料充分的短问题，例如“什么是栈？”；
5. 回答底部模型元数据应显示上游实际使用的模型，不得静默回退为另一模型；
6. 改选 `deepseek-v4-flash` 再提一题，确认新回答记录新的实际模型；
7. 刷新页面后，模型选择恢复后端默认值 `deepseek-v4-flash`。

若某个白名单模型被上游账号拒绝，应显示模型服务错误；这不应被伪装成另一个模型成功回答。

### 2. 会话保存与继续

1. 在“数据结构”课程中新建课程对话并连续提交两道相互独立的问题；
2. 页面应按“用户问题 → 助手回答 → 用户问题 → 助手回答”显示完整顺序；
3. 每个助手回答的引用、文件位置、检索诊断、模型和 Token 信息应保留；
4. 刷新页面，消息顺序、回答正文和引用仍应恢复；
5. 从侧栏“学习助手对话”进入该记录，内容应与刷新前一致；
6. 侧栏“最近对话”不得出现这条课程会话。

### 3. 课程隔离与删除

1. 在已有课程会话中切换课程，页面应退出原会话，不能把旧消息继续显示在新课程范围内；
2. 重新从侧栏进入旧会话，应自动恢复其绑定课程；
3. 点击侧栏记录右侧删除按钮并确认；
4. 记录应从侧栏消失，对应历史路由不再可访问；
5. 删除会话不应删除课程、资料或向量索引。

## 通过标准

- 两个模型均可选择，后端拒绝白名单外模型；
- 回答记录显示实际使用模型，不暴露 API Key；
- 消息、引用和诊断元数据可刷新恢复；
- 课程会话不跨课程读取，也不进入快速对话历史；
- 删除只影响目标会话及其消息；
- 不要求本日回答理解历史指代，不要求流式逐字显示。
