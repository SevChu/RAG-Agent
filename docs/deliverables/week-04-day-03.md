## 完成范围

### 对话自动路由

- 课程学习助手继续使用原有输入框和 SSE 接口，不新增总结专用页面；
- LangGraph `RequestRoutingGraph` 自动区分课程问答与知识总结；
- 总结、归纳、梳理、复习提纲、知识框架、考试重点等明确请求进入总结分支；
- “总结和回答的区别是什么”等把“总结”当作讨论对象的问题仍走问答分支；
- 路由类型和可解释原因写入会话检索快照，刷新或打开历史记录后仍可展示。

### 总结范围

- 未指定更小范围时默认总结当前课程；
- 请求中出现章节、知识点或 topic/chapter 时按主题范围检索；
- API 明确传入 `document_ids`，或请求中包含课程文件完整名称时，限定到指定资料；
- 只使用状态为 `completed` 的课程资料；显式选择未完成资料时沿用既有冲突保护；
- 总结使用独立的 40 条候选、Top 12 重排配置，可通过环境变量调整。

### 结构化总结与引用校验

服务端要求模型返回 Pydantic 约束的 JSON 字段，再固定组装为以下结构：

1. 核心概念；
2. 重点知识；
3. 知识关系；
4. 常见错误；
5. 示例或应用；
6. 复习建议；
7. 考试重点；
8. 资料引用。

总结默认且强制为课程资料范围：

- 不调用 Web Search，即使界面问答来源选择为“课程资料 + 外部补充”；
- 只接受 `[课n]`，拒绝 `[外n]`、模糊 `[n]` 和越界编号；
- 服务端以正文实际出现的引用为准，不信任模型声明的编号数组；
- 资料引用部分由服务端根据已验证引用生成，展示文件名和章节路径；
- 没有合格证据时不调用总结模型，返回明确的资料不足说明。

### 前端交互

## 用户验收建议

1. 启动后端和前端，打开 `http://127.0.0.1:5173/assistant`；
2. 选择一门已有完成入库资料的课程；
3. 输入“总结整个课程”，确认自动显示“课程知识总结”，且包含 8 个部分；
4. 输入“总结第 3 章的考试重点”，确认范围提示为章节或知识点；
5. 输入“总结 文件完整名称”，确认只在该文件范围检索；
6. 展开两条引用，核对正文 `[课n]` 与文件、章节、页码一致；
7. 保持问答来源为“课程资料 + 外部补充”，再次总结，确认仍显示“仅课程资料”且没有外部引用；
8. 再问一个普通问题，确认仍走课程问答并保留计划日 2 的条件外部搜索能力；
9. 刷新页面或从侧栏重新打开对话，确认总结结构、引用和路由说明仍在。

## 首轮验收反馈与修复

用户首轮验收时，“总结整个课程”和“总结第三章的考试重点”均错误返回证据不足。读取实际
会话诊断后确认：两次请求都已召回 40 条候选并返回 12 条通过内容角色检查的片段，但总结
生成器又错误复用了精准问答的 `0.3` 相似度门，导致宽范围总结候选被全部二次过滤；同时
章节解析只枚举了阿拉伯数字，没有识别“第三章”。

修复内容：

- 总结直接使用已经过 Reranker 排序和内容角色安全门的 Top 12，不再应用问答事实定位阈值；
- 普通问答仍保留原有相似度阈值，未放宽 Day 2 的证据门；
- 章节范围支持“第3章”“第三章”“第十二章”“本章”“这一章”等表达；
- 全课程检索查询保留用户原始要求，不再替换成同一个通用查询；
- 新增低至 `0.02` 的宽范围总结证据回归测试，以及中文章节范围测试。

使用用户原句在实际课程重新验证：
