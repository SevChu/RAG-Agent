## 建议验收顺序

以下八项与开发侧真实课程审计一致。第 1～7 项建议新建独立课程对话；第 8 项必须在同一对话中
连续发送两段消息，以验证上下文续写。

### 1. 仅课程普通问答

来源范围选择“仅课程资料”，发送：

> 栈的基本特点是什么？请根据课程资料回答。

通过标准：自动走普通问答；至少一个 `[课n]`；外部搜索显示未请求；回答和引用可刷新恢复。

### 2. 明确外部补充

来源范围选择“课程资料 + 外部补充”，发送：

> 结合当前课程关于栈的内容与外部 C++ 标准库资料，说明 std::stack 与课程栈抽象的对应关系。

通过标准：走普通问答并触发外部搜索。搜索成功时 `[外n]` 可打开且正文编号一致；若恰逢搜索
失败，应显示失败和安全降级，不能无限加载或返回 HTTP 503 原始正文。该请求不应误路由为总结。

### 3. 工程取舍总结

发送：

> 从“工程取舍与可维护性”的角度总结哈希表。

通过标准：自动进入动态总结；强制 `course_only` 且不搜索；计划目标、关注方向和章节围绕工程
权衡与维护性，而不是套用“核心概念—考试重点”的固定同质模板；正文只有 `[课n]`。

### 4. C++ 实现总结与流式恢复

发送：

> 从 C++ 实现角度总结二叉树遍历，重点说明函数结构和容易写错的边界。

通过标准：等待阶段后正文逐步出现；不能再报正文引用与声明不一致；刷新并从历史进入后，动态
计划、质量诊断、引用和完整正文仍在。如果课程资料没有某段具体代码，可以明确资料限制，不能
用无来源代码填充。

### 5. 无答案、无解析试卷

发送：

> 请根据栈相关内容出一份仅含3道判断题的试卷，答案和解析都不要，仅课程资料。

通过标准：自动进入组卷；正好 3 道判断题；正文和历史均无“答案”“解析”；每题有课程来源；
来源上限与内部证据审查通过。若质量卡显示近似重复题号，可按已确认策略人工复核，但不能再次
出现“单题批次没有按格式返回”或因隐藏答案导致证据审查失败。

### 6. 只含答案、不含解析试卷

发送：

> 请根据排序章节出一份仅含3道单选题的模拟卷，只要答案，暂时不用输出解析，仅课程资料。

通过标准：正好 3 道单选题，每题至少 A/B/C/D 四项并显示答案；没有解析；来源上限、引用和逐题
证据审查通过。刷新后输出开关和质量信息保持一致。

### 7. 默认答案和解析的三道单选题

发送本轮实际失败原句：

> 请根据排序章节出一份仅含3道单选题的模拟卷。

通过标准：正好 3 道单选题；默认显示答案和解析；每题至少 A/B/C/D 四项；引用、来源比例和逐题
证据审查通过。若模型只返回 A/B/C 且答案明确位于现有项，服务端可以补入逻辑假 D 干扰项；若
答案指向缺失项则仍须重试，不能靠补项掩盖错误答案。不应再出现“选择项少于 4 个”，也不应在补项
后因该逻辑干扰项未写入教材而误报证据不支持。

### 8. 对上一份试卷补充答案与解析

在同一个新课程对话中依次发送：

> 请根据队列相关内容出一份仅含3道判断题的试卷，答案和解析都不要。

等待第一轮完整结束后，再发送：

> 现在给出答案和解析。

通过标准：第一轮正好 3 题且不显示答案、解析；第二轮仍走 `exam`，展示同一组三道题的答案和
解析，题号和题目不得变化；第二轮不重新检索、不重新出题，不应再出现“模型没有按混合回答格式
返回结果”。刷新历史后四条消息完整存在，第一轮仍不得泄露内部答案。修复前已经生成的旧试卷也
可以依据原可见题目和当时保存的课程证据补充答案；该兼容路径不会另出新题。

## 整体验收标准

- 八类请求均从原课程助手输入框自动路由，无需新增模式开关；
- 普通回答、总结和组卷都能随历史恢复，SSE 完成消息不会丢失计划或诊断；
- 总结只使用课程资料，并能根据用户目标产生明显不同的动态结构；
- `[课n]`、`[外n]` 命名空间、搜索状态、冲突/降级和来源卡一致；
- 组卷题量、题型、答案/解析开关、教材 30% 与外部 20% 上限严格生效；
- 无答案卷不泄露内部教师答案；单题局部修复可以接纳安全可推导的直接对象格式；
- 紧邻试卷的答案/解析续问恢复同一份后端工件，不把续问误送到普通混合回答分支；
- 页面没有 API Key、课程原始上下文、内部审查 JSON 或未保存的失败回答泄露。
