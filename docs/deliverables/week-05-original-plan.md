# 第 5 周实施计划：评测、长上下文、课程空间记忆与调优

## 本周目标

第五周继续以量化评测和参数调优为主线，同时在冻结旧基线后加入同会话 100k 长上下文和仅限
同课程的跨对话记忆。最终必须用同一批标注样本比较旧方案、新长上下文方案和课程记忆方案，不能
只以页面观感宣布改进。

本周完成标准：

- 建立不少于 50 条、按文档或章节隔离的独立评测集；
- 保存第 4 周最终版本的 M0/RAG 基线结果；
- 同一对话历史由“最近 6 条”升级为模型感知的动态预算，默认方案上限为 100k tokens；
- 实现仅限同一 `course_id` 的结构化长期记忆及用户管理入口；
- 完成 RAG 消融、M0/M1/M2 记忆对照、阈值调优和人工抽查；
- 输出可复现的配置、指标、延迟、Token 消耗和结论报告。

详细边界见[课程空间记忆与同会话长上下文设计决策](../design-decisions/course-memory-and-long-context.md)。

## 计划日 1：冻结基线与评测基础设施

### 实施内容

- 固定当前 Git 提交、模型、课程资料版本、分块配置、检索参数和随机种子；
- 建立评测数据契约、CLI/服务层、结果持久化和可恢复 token 账本；
- 汇总第三、四周真实失败问题并形成不少于 50 条评测集骨架；
- 覆盖普通问答、拒答、混合来源、动态总结、混合组卷、多轮上下文和课程隔离；
- 在未修改上下文逻辑前运行 M0 基线，保存最近 6 条/6000 字符的表现；
- 建立人工标注与 LLM-as-Judge 分离的复核流程。

### 验收

- 可以列出数据集版本、样本类型和训练/验证/测试隔离情况；
- 中断评测后可从 token 账本继续，且不会重复扣除已完成样本；
- M0 报告包含检索、答案、引用、拒答、延迟和 token 指标；
- 未经批准不会启动超出独立预算的真实模型调用。

## 计划日 2：同会话 100k 长上下文

### 实施内容

- 增加模型上下文能力表和统一 token 预算器；
- 将固定 6 条/6000 字符改为动态最高 100k tokens；
- 增加最近原文、较早相关历史和滚动摘要的分层选择；
- 保持试卷后续答案/解析、查询改写和课程证据边界；
- 记录上下文选择、token 估算和降级原因；
- 使用本地假模型构造接近及超过 100k 的边界测试，真实模型只做小规模连贯性冒烟。

### 验收

- 同一对话中第 7 条以前的信息仍可在后续追问中被正确使用；
- 合成历史达到 100k 上下限时不出现超窗请求，超过后按规则裁剪；
- 课程资料引用仍来自检索证据，不能引用聊天历史代替教材；
- M1 与 M0 的长程指代、token 和延迟对比可复现。

## 计划日 3：课程空间长期记忆后端

### 实施内容

- 新增课程记忆数据表、迁移、服务、仓储和 API；
- 实现显式“记住/忘记”和保守的自动候选提取；
- 实现同类合并、冲突替换、停用、删除和课程删除级联；
- 回答前只检索当前 `course_id` 的相关记忆；
- 将记忆作为教学偏好上下文，不作为课程知识证据；
- 提取失败或服务异常时安全降级为无记忆问答。

### 验收

- 在课程 A 的对话 1 中声明默认 C++，新建对话 2 后仍能遵循；
- 课程 B 和快速对话完全读取不到课程 A 的记忆；
- “忘记默认语言”后新对话不再使用该偏好；
- 模型生成的试卷答案不会被自动保存为学习记忆；
- 删除课程会删除对应记忆且不影响其他课程。

## 计划日 4：记忆管理界面与集成回归

### 实施内容

- 在课程设置增加启用状态、分类列表、来源时间、编辑、删除和全部清空；
- 在回答诊断中展示使用记忆数量和长上下文统计；
- 补齐刷新恢复、并发更新、冲突偏好、来源对话删除和提示注入测试；
- 验证总结仅课程、组卷来源比例和独立会话默认联网不受影响；
- 完成 M2 集成候选版本并冻结待评测配置。

### 验收

- 页面可以查看、编辑、删除和 Reset 当前课程记忆；
- Reset 不删除课程资料、聊天正文和累计 token 统计；
- 关闭自动记忆后不新增候选，但现有记忆按产品开关定义处理；
- 前后端自动化、数据库迁移检查和浏览器关键路径全部通过。

## 计划日 5：量化对照、参数调优与周报告

### 实施内容

- 完成不少于 50 条样本的最终标注和锁定；
- 运行 E0～E5 中当前工程可执行的 RAG 消融，未实施的领域微调单独标记；
- 运行 M0/M1/M2 对照，评估长上下文和课程记忆的净收益；
- 调整 Top-K、相似度阈值、外部搜索触发、拒答阈值、历史预算和记忆选择上限；
- 对自动指标进行人工抽查，记录失败类别而不是只报告平均分；
- 输出实验报告、推荐默认参数、已知限制和第 6 周交付入口。

### 验收

- 每个实验只改变一个主要变量，配置与结果可追溯；
- 报告包含检索、忠实性、引用、拒答、记忆、隔离、延迟和 token 成本；
- 跨课程记忆泄漏为 0，删除后的记忆使用次数为 0；
- 用户可根据报告决定是否把 100k 与自动课程记忆设为正式默认值；
- 工程日志沿用第 1～3 周结构，记录问题、原因、处理、测试证据和 Git 提交。

## 实施顺序约束

1. 必须先完成计划日 1 的旧版基线，再修改上下文与记忆逻辑；
2. 每个计划日开始前列出真实模型调用范围和预算，收到用户批准后才执行；
3. 每个计划日完成后提供页面/API 验收步骤，用户验收前不创建 Git 提交；
4. 计划日 2～4 的功能验收不能代替计划日 5 的独立量化评测；
5. 本计划不包含全局用户画像、跨课程记忆、云端同步、多人账户或模型微调训练。

## 实施前需要用户确认

- 100k 是默认上限还是设置中的可选档位；
- 新建课程是否默认开启自动记忆；
- 第五周真实 DeepSeek 调用的总 token 预算；
- 是否允许记忆在删除来源对话后继续保留（计划默认保留已确认记忆，并标记来源已删除）。
