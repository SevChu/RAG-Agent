- 包含隐藏文件、依赖和 Git 元数据；各分类互斥。目录链接不递归进入，本次未发现目录链接。
- `backend/.pytest_cache` 因文件系统权限无法遍历，其体积未计入；总量是可读取部分的合计。

## 本轮已完成的优化

1. **检索评测复用累计结果**：`backend/app/evaluation/retrieval.py` 在多个 Top-K 截断点间累计相关命中数、倒数排名、平均精度和 DCG。每个查询只排序一次理想相关度列表，避免每个截断点重新切片和多次扫描。保留指标名称、截断点归一化、缺失查询、分级相关度及原有重复命中处理方式。
2. **合并实验辅助函数**：将 RAGTruth 和 RAGBench 脚本中完全相同的 `model_identity`、`resolve_device`、`hardware_info` 提取到 `backend/scripts/benchmark_runtime.py`。两份原脚本继续导入并暴露原名称，供已有调用方使用。

三个原文件加新增共享模块，源码由 **1,792 行减至 1,736 行，净减少 56 行**；统一 LF 后减少 **1,651 字节**。另增加两项检索边界回归测试，共 37 行。上述精简行数不把新增测试算作业务代码，也没有把函数搬家当成删除。

未调整模型、提示词、评分定义、冻结实验 profile、API 或数据库结构；首次代码优化阶段未删除原有模型、数据、依赖或缓存。未修改前端业务代码；后续缓存清理见末节。

## 后续瘦身优先级

1. **空间回收优先检查开发缓存**：扫描时根目录与后端的两个 Mypy 缓存合计约 **248.0 MiB**；这类缓存可重建，清理会增加下次检查耗时。`tmp` 原有约 **160.8 MiB**，混有验收记录、PDF 和历史测试文件，应先确认保留价值，再按具体目录清理。缓存/临时/构建合计 412.5 MiB 不代表可以全部无条件删除。
2. **依赖是另一主要占用**：后端 `.venv` 约 **5.283 GiB**，前端 `node_modules` 约 **254.3 MiB**；其中 Torch 目录约 **4.09 GiB**。删除 CUDA 或 OCR 组件可能改变 GPU/OCR 能力，不属于直接保持功能的精简。本轮未改依赖版本或安装方式。
3. **大文件可继续按职责拆分**：`generation/exam.py` 1,716 行、`generation/summary.py` 1,162 行、`api/routes/qa.py` 1,323 行、`StudyAssistantView.vue` 1,241 行。后续适合分别梳理输入规范化、生成校验、渲染、路由编排和页面状态；拆文件主要改善可维护性，本身不保证总行数或运行耗时降低。
4. **实验代码有明显分量但承担现有能力**：脚本约 8,932 行，占原始全部源码行数约 21%。可继续抽取共享实验基础逻辑，保留命令行入口及实验复现能力；不能仅因脚本较旧就认定为无用代码。

本次生成的测试目录和 Mypy 缓存已在验证结束后清理。统计快照描述的是审计开始时的项目，不会把本次产生的临时文件混入原有占用。
