## 升级前审查与备份

1. 确认安装路径、发行类型、代码身份、实际数据库和资源路径，记录当前 revision、配置与磁盘容量。
2. 停止新提交，等待资料索引完成；如果已有训练，等待终态或通过 API 取消。正常停止后端和 worker，
   检查进程与写入锁已释放。不能只关闭浏览器就开始备份。
3. 在全新备份目录成组保存 SQLite、uploads、Qdrant、存在的 TRAINING_DATA_DIR 和私有 .env；
   保留升级前代码包、模型版本及哈希。数据库可用 SQLite backup 接口；不能在活动写入时仅复制主文件。
4. 在隔离目录验证备份可打开、integrity_check/foreign_key_check、原业务行与文件哈希；以副本演练
   06→07→08→09、ORM 对照及恢复。恢复演练目标必须是副本，不写回原库。
5. 向维护负责人提交具体停机、备份、写入、启用和恢复范围，审查通过再操作正式实例。

## 执行迁移和关闭后台核验

在确认的 backend 目录执行；先在对应环境设置 `TRAINING_WORKER_ENABLED=false`，停机期间切换
候选源码和匹配依赖环境，保留私有配置与数据。已有环境不需要为了 beta 重装或升级第三方依赖。

```powershell
.\.venv\Scripts\python.exe -m alembic current
.\.venv\Scripts\python.exe -m alembic heads
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic current
.\.venv\Scripts\python.exe -m alembic check
```

确认 revision=09、无临时迁移表、完整性/外键通过，原记录和上传/向量文件一致。以 worker=false
启动一个后端进程，检查健康、配置、旧智能体及两类会话的只读接口，确认没有误连新空库。
健康接口不是检索和模型可用性证明；本次 Fake 验证无需调用真实供应商。

## 显式启用科研模拟 worker

确认 research 能力和独立 TRAINING_DATA_DIR 后，在受保护的配置中设置
`TRAINING_WORKER_ENABLED=true`，正常重启后端：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

维护和正式使用不加 --reload。前端连接 `http://127.0.0.1:8000/api`，必须包含 /api；更改
VITE_API_BASE_URL 后重启对应 Vite 进程。不要启动第二个后端访问同一 SQLite/Qdrant。

用已获准的一组合成数据验证：登记/审核 → 五步提交 → 事件进度 → succeeded → 唯一模拟 Adapter。
确认 deployable=false、not_evaluated，取消/重试不改写历史；结束后检查无遗留运行任务及异常日志。
worker 开关不是活性证明，应结合实际任务和事件。未配置 OS 自启动，进程管理由部署者负责。

## 回退与恢复

- 优先停止接收新任务、正常停止进程并关闭 worker；服务异常不等于需要立即回滚数据库。
- 恢复前另存当前数据和新产生的任务/产物证据，避免覆盖事故后的信息。
- 若需完整回退，使用同一备份集恢复数据库、文件目录、配置与匹配旧代码；先在副本验证，再按批准
  范围停机恢复正式实例。旧备份不会包含备份之后新增的训练记录，必须明确接受这一时间点损失。
- 不在含需保留训练历史的正式库上随意 downgrade：会删除新增表/触发器但保留磁盘文件，造成引用丢失。
- 不手工把模拟状态改成真实/可部署，不覆盖损坏清单来冒充完整性恢复。
- 恢复后保持 worker 关闭，复核版本、业务记录、文件来源和无写入异常；确认后再决定启用。

历史成功任务固定原代码身份；新代码不重写旧快照。升级期间排队任务若身份预检失败，先核对原因，
再显式重试为新任务；不保证跨版本续跑，更没有真实训练 checkpoint 恢复能力。
