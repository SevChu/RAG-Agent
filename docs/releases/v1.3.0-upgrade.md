## 从旧版本升级

适用于包含 20260910_06 的源码。操作前确认使用的 .env、数据库地址、上传目录和 Qdrant
目录，不能假定所有安装都使用默认 data 路径。

1. 停止后端和写入/索引任务，保持 SQLite、上传文件与 Qdrant 一致。
2. 在仓库外备份三类业务数据。SQLite 使用 backup API 或在确认无写入且 WAL 完整处理后
   备份，不能仅复制正在写入的 app.db 而遗漏 WAL。记录版本、时间、文件清单和校验哈希。
3. 先在独立副本演练升级，核对旧表内容、外键、SQLite 完整性及 uploads/Qdrant 未被修改。
4. 在项目 backend 目录使用已有环境运行：

```powershell
uv run alembic current
uv run alembic upgrade head
uv run alembic current
uv run alembic check
```

目标为 20260910_06。首次安装也使用同一迁移链；不要删除旧迁移脚本或用删除数据库替代升级。
命令应使用与启动后端相同的配置。升级和检查失败时先保留现场，不能直接重建空库继续。

5. 核对旧资料/会话/消息/Token 记录数量和原列内容保持一致，旧会话两个绑定字段均为空，
   无外键错误或 _alembic_tmp 残留。随后按 README 启动并验收默认旧会话和新智能体入口。

## 本迁移改变什么

创建 agent_profiles 与 agent_profile_revisions，为 conversations 增加可空身份/版本绑定。
配置快照与历史绑定通过约束和触发器保护；已有消息、引用、资料和向量内容不重写。
这次 SQLite 表重建由迁移脚本管理外键状态并在前后检查，不能手工仿写为删除旧表。

正式执行及旧表内容哈希一致的证据见 [Day 1 升级记录](../deliverables/week-07-day-01-database-upgrade.md)。
Day 5 的复核仅证明当前完整性和备份数据库哈希，未重新读取全部真实资料做外部验证。

## 恢复与降级

优先在停止写入后，保存当前失败状态，再从已核验的完整备份恢复 SQLite、uploads 和 Qdrant，
配套使用该备份对应的代码与配置。恢复会丢失备份之后的新记录，执行前必须明确时间范围。
先在独立恢复目录验证后再切换，不覆盖唯一可恢复副本。

Alembic 可降到 20260810_04，但会删除新增智能体及 revision，并移除会话绑定；旧会话和消息
在迁移测试中保留。此操作不可恢复配置审计历史，不能把降级当作日常清理。需要保留本周
智能体/会话关联时不要执行降级。本轮没有对正式库执行降级或恢复。
