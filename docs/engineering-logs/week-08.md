## 历史基线与本周定位

前几周已经形成资料空间、RAG 检索与生成、公开评测基线和版本化 AgentProfile。第七周解决了
智能体配置、会话固定版本与产品/科研分离，但尚无训练数据审核、可恢复任务或产物追踪流程。

第八周先搭建平台，使用 FakeTrainer 验证数据到任务再到模拟 Adapter 的完整生命周期。首轮目标是
来源可追溯、任务可管理、失败可诊断、界面可操作；不以模型质量提升或生成真实权重作为本周验收项。
真实 Reranker/Scorer 训练、评测晋级、运行绑定和回滚安排在第九周。

实施依据为[第八周每日计划](../deliverables/week-08-plan.md)。用户批准计划后逐日验收，要求正式
变更和高风险事项先审查；Day 2 获准提前开展数据副本演练，正式库与 worker 切换仍在 Day 5 单独批准。

## 本周确认约束

1. 数据版本、任务来源和产物身份可追溯，不覆盖已有快照或失败历史。
2. 训练 Registry 只接受 train/validation；不读取封存 test，不自动把资料和会话转换为训练样本。
3. 来源、许可和 PII 需明确记录，规则扫描不能替代人工审核。
4. FakeTrainer 不下载模型、不调用生成供应商、不计算梯度；模拟 Adapter 始终不可部署、未评估。
5. 数据库、worker 和生成模型路由分开配置，切换界面或审核数据不自动授权正式训练。
6. Day 1～4 使用隔离环境；正式变更先备份、验证恢复副本、审查操作范围，再分阶段执行。
7. 产品包不含训练/评测模块，普通业务不依赖 Benchmark；共用模型和迁移仍维持数据一致性。
8. 不升级第三方依赖、不清理既有模型、数据或备份；本地私有资产不进入发布物。
9. 功能验收与发布授权分开；用户要求本周技术文档审阅通过后方可发布。

### 当日目标

建立可追溯的数据身份、不可变内容版本、追加审核及资格检查，为后续训练任务提供可信来源。

### 当日明确不做

不实现训练任务、Adapter 或微调页面；不迁移正式数据库，不下载模型、数据或训练依赖。
自动验证使用合成样本和隔离数据库，不调用真实供应商。

### 实际完成内容

新增三张数据元信息表、六个不可变触发器及 `20260911_07` 迁移，提供 10 个 HTTP 操作。
支持受控 JSONL/manifest 导入、Scorer/Reranker 字段、来源与 group 检查、精确及近重复检测、
基础 PII 模式扫描，以及内容、manifest 和 split 哈希。

数据修改创建新 revision，审核事件只追加；row_version 防止并发覆盖。资格检查复核审核、文件、
智能体启用状态和空间范围。上传文件名不参与存储路径，请求、文件、行数及去重工作量均有限额。
产品包排除 Python 训练管理模块，保留共用迁移。

### 关键设计决策

- 数据内容与审核历史分开管理；撤销不会删除原记录。
- 仅接受 train/validation，拒绝 test 与别名；不从用户资料或会话自动收集样本。
- 审核署名用于本机审计，不等同于账号认证或双人标注。
- 文件写入成功而数据库提交失败可能留下未引用文件，不自动删除。

## 计划日 2：持久化任务与 FakeTrainer

### 基本信息

- 实施日期：2026-09-11。
- 状态：实现、回归及获准的数据副本演练完成，用户验收后授权 Day 3。
- 交付：[Day 2 报告](../deliverables/week-08-day-02.md)、[副本演练](../deliverables/week-08-day-02-copy-rehearsal.md)。

### 当日目标

使任务能够持久记录来源、进度和事件，并正确处理重复提交、取消、失败重试与 worker 失联。

### 当日明确不做

不升级正式库或启用正式 worker；不实现 Adapter Registry、真实训练、权重加载或运行绑定。
数据副本仅用于保留历史与兼容检查，训练仍使用独立合成样本。

### 实际完成内容

新增任务、事件、单例租约三表和 `20260911_08` 迁移，13 个触发器保护身份、状态、进度、终态、
事件及依赖撤销。实现幂等提交、冻结来源、取消、显式重试、后台领取与心跳、过期租约恢复。
任务选项、估算、创建、列表、详情、事件、取消和重试共 8 个 API 接入。

FakeTrainer 生成模拟结果描述，不产生 Adapter 文件。worker 默认关闭，在 research 模式显式启用
后由应用生命周期管理。产品包不导入训练模块，共享 SQL 迁移仍维护来源撤销与历史保留。

用户批准提前演练后，通过 SQLite 只读备份接口建立原始快照、迁移往返副本和运行副本。7 次迁移
操作保持原七张表的 48 条业务记录与结构；运行副本完成 7 组场景，7 个任务最终为成功 2、取消 2、
失败 1、中断 2。结束时副本 worker 关闭、租约释放，原库和 .env 未变。

### 关键设计决策

- SQLite 独立写事务协调任务与来源撤销，避免资格检查和提交之间的竞态。
- owner_token 和租约有效期限制回调，过期 worker 无权写回进度或成功。
- 重试创建新 run，保留 retry_of 和原来源，重新核验当前资格，不覆盖失败历史。
- 模拟检查点的停止能力不等于真实 GPU 进程强杀或 checkpoint 续训。

| `backend/app/models/training_run.py` | 任务、事件与租约模型及约束 |
| `backend/migrations/versions/20260911_08_training_runs.py` | 冻结迁移与来源取消触发器 |
| `backend/app/training/run_store.py`、`run_schemas.py` | 事务、快照、幂等与状态机 |
| `backend/app/training/trainer.py`、`worker.py` | 模拟协议、后台循环和恢复 |
| `backend/app/training/run_routes.py` | 八个任务操作 |
| `backend/tests/test_training_runs.py`、`test_training_run_migration.py` | 生命周期、竞争与迁移测试 |

Mypy 126 源文件通过；前端 25 passed，类型/Lint/1,756 模块构建通过。实际产品包 80 passed、
1 deselected，无训练/评测模块或 PyArrow 导入。

两日迁移往返和旧 Registry/业务保留通过。30 ms 检查点的两次取消测量约 62/94 ms，副本演练

## 已知问题与技术债务

1. FakeTrainer 无梯度或权重训练；真实训练时间、显存和成本尚未实测。
2. 文件与数据库没有跨介质原子事务，异常可能留下孤儿文件；不自动删除或覆盖损坏产物。
3. 单机 SQLite 租约不等于分布式调度、真实 GPU 子进程强杀或 checkpoint 恢复。
4. PII、许可与近重复规则不能覆盖全部语义、来源和数据污染风险，需人工审核。
5. 审核署名和 product/research 模式不是多用户认证或科研源码保密机制。
6. 训练代码哈希不是完整 commit/依赖环境快照，长期任务与事件保留策略仍需明确治理。
7. 一项原生 symlink 测试受本机权限限制跳过；尚未执行全新联网安装或完整断电灾备。
8. 正式备份位于同一本地磁盘，当前没有系统自启动、持续监控或自动恢复编排。
9. 真实 Adapter 的权重清单、加载、评测晋级、指定 revision 绑定与回滚尚未实现。
