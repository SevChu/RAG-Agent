#### 课程 API

2. 提交数据库级联删除；
3. 数据库失败时恢复原文件目录；

#### 文档 API

- `POST /api/courses/{id}/documents`：上传资料；
- `GET /api/courses/{id}/documents`：课程资料列表；
- `GET /api/documents/{id}`：资料详情；
- `GET /api/documents/{id}/status`：索引状态；
- `DELETE /api/documents/{id}`：删除单份资料。

文档上传会：

1. 验证课程存在；
2. 净化原始文件名；
3. 检查允许的扩展名；
4. 以 1 MB 分块写入临时文件；
5. 写入过程中计算大小和 SHA-256；
6. 拒绝空文件或超过 100 MB 的文件；
7. 验证内容与声明格式基本一致；
8. 使用文档 UUID 生成内部文件名；
9. 将文件移动到课程目录；
10. 提交数据库记录；
11. 数据库写入失败时清理已移动文件。

#### 文件内容校验

- PDF 必须以 `%PDF-` 文件头开始；
- DOCX 必须为 ZIP 容器并包含 `word/document.xml`；
- PPTX 必须为 ZIP 容器并包含 `ppt/presentation.xml`；
- Office 文件必须包含 `[Content_Types].xml`；
- Markdown 和 TXT 必须为 UTF-8；
- 文本文件不能包含空字节；
- CSV 等未列入白名单的扩展名直接拒绝。

### 关键设计与决策

1. 上传文件以 1 MB 分块处理，避免一次性载入最多 100 MB 的完整文件。
2. SHA-256 在写入临时文件时同步计算，不额外完整读取一次文件。
3. 原始文件名仅用于展示；内部存储名使用文档 UUID，防止覆盖和路径注入。
4. 文件类型同时检查扩展名和最低限度的容器特征，不信任浏览器提供的 MIME 类型。
5. 同课程重复由 `(course_id, sha256)` 数据库约束最终兜底，能够处理并发竞争。
6. 相同 SHA-256 在不同课程允许存在，保持课程空间隔离。
7. 删除采用“先移动、再提交、失败恢复”的补偿流程，降低数据库和文件系统不一致风险。
8. `.staging` 和 `.trash` 属于运行时目录，均位于未提交的上传数据区。

#### 冲突提示无法区分资源

课程同名和资料内容重复都使用 `CONFLICT`，前端原本显示同一条包含两种含义的提示。根据后端返回的具体资源信息细分中文提示，并增加两个参数化测试，浏览器复验同名课程提示通过。

#### 手机侧边栏隐藏语义不完整

侧边栏关闭时原本只通过 `transform` 移出屏幕，浏览器可访问树仍包含不可见导航，而且抽屉内没有明确关闭按钮。增加可见性控制和手机专用关闭按钮后，关闭状态不再暴露侧边栏节点，打开和关闭位置均通过实际视口验证。
