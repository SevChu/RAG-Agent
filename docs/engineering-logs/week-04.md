## 周目标

本周在第三周课程 RAG、会话和 SSE 基础上，将学习助手从单一问答链路扩展为可自动识别任务、
按需调用外部信息并生成课程总结的 Agent。实现顺序强调先建立来源契约和失败边界，再接入
LangGraph 条件编排，最后扩展总结与出题，避免把联网、总结和组卷同时塞入一个不可验证的
生成节点。

本周计划覆盖以下能力：

1. 建立课程资料与外部来源的双命名空间引用、搜索状态和持久化契约；
2. 依据课程证据覆盖程度决定是否搜索，生成可核验的混合答案；
3. 在外部搜索失败时保留已有课程回答，并显式说明降级状态；
4. 从同一课程对话入口自动路由普通问答、课程总结和后续出题任务；
5. 总结始终受课程证据约束，并能依据用户真实目标改变内容结构；
6. 在总结契约稳定后接入混合组卷、来源比例和编程语言规则。

## 周验收标准

- “仅课程资料”模式绝不调用 Web Search，混合模式也不会对所有问题无条件联网；
- 混合回答中的 `[课n]` 与 `[外n]` 均可回到真实来源，不接受模糊或越界引用；
- 外部服务超时、HTTP 5xx、无合格来源时不会拖垮课程已经能够回答的部分；
- 同一对话输入框能自动区分普通问答和总结，且路由结果、范围与诊断可随历史消息恢复；
- 总结只使用课程资料，明确的总结方向不会被统一模板稀释；
- 出题默认 20 题、语言每次可选且默认偏向 C++，课程改编题不超过 30%，外部补充题不超过
  20%；
- 每个计划日分别通过后端测试、静态检查、前端测试与构建，并提供可由用户复现的验收入口。

### 关键设计与决策

1. **先固化来源契约，再接入生成链路。** 外部搜索结果只有进入独立的 `external` 来源空间后
   才能交给生成器，避免计划日 2 再修改所有响应和历史消息结构。
2. **课程与外部引用独立编号。** `[课1]` 与 `[外1]` 可以同时存在，用户无需根据一张混排清单
   猜测某个编号属于教材还是网络。
3. **真实 URL 是外部证据的最低门槛。** 模型生成的来源名称、记忆中的网页或无法与工具结果
   对齐的摘要均不接纳，防止“看起来像引用”的内容进入答案。
4. **质量筛选采取允许类别加低质量过滤。** 学术、大学、科研机构、标准组织和官方文档优先；
   论坛、自媒体和聚合页不因标题相关就进入合格证据。
5. **旧会话按课程范围解释。** 新字段存入现有 JSON 快照而不是立即迁移数据库，缺失字段时
   采用第三周语义，确保历史记录仍可打开。
6. **计划日边界必须在界面可见。** 范围选择器可以先落地，但页面明确说明本日尚未将搜索
   接入正式答案，避免把基础设施误认为已经完成混合问答。

### 问题及处理

#### 外部搜索响应正文不可直接作为公开证据

服务端工具返回的搜索正文包含不可直接读取的加密内容块，不能把模型随附的文字自动当作网页
原文。适配器因此把“工具给出的真实 URL”和“同次响应生成的摘要”分开处理：仅当摘要声明的
URL 能与工具结果严格对齐时才接纳，并在界面中明确标为证据摘要而非逐字网页摘录。

#### 真实服务偶发 HTTP 503

验收搜索时出现过一次 HTTP 503，重试后成功。这不是课程资料或前后端入口错误，而是上游服务
暂时不可用。计划日 1 将其转换成结构化 `failed` 状态并隐藏敏感响应；计划日 2 再依据这一状态
完成课程答案降级。

#### 新范围选择器可能造成能力误读

前端已经能选择“课程资料 + 外部补充”，但本日尚未把搜索结果送入生成器。为避免用户误以为
答案已混合联网内容，界面增加阶段说明，验收标准也明确计划日 1 不检查正文 `[外n]`。

- 搜索成功后把课程证据与外部证据分别编号，生成器只接受 `[课n]`、`[外n]`；

- 模型声明或正文出现来源冲突时，必须生成“资料差异”部分并同时引用双方证据；
- 最终引用列表以正文实际使用且校验通过的编号为准，不把未使用结果全部展示成答案来源。

#### 失败降级与可观测性

- 搜索超时、HTTP 错误、无合格来源或适配器异常时不直接终止问答；
- 存在合格课程证据时回到课程生成并记录 `fallback_applied=true`，否则保持证据不足拒答；
- 前端展示条件搜索原因、合格与采用来源数、安全降级提示、来源差异状态和外部引用链接；
- 搜索判断、失败原因、采用数量和冲突标志随回答写入会话快照，无需数据库迁移。

### 关键设计与决策

1. **搜索决定由可解释规则完成。** 当前不为“是否联网”额外调用一次 LLM，控制响应成本和
   不确定性；阈值通过配置暴露，留待第五周评测数据校准。
2. **`course_only` 是硬隔离而非提示词偏好。** 该范围从图的条件边直接绕过搜索节点，即使
   用户问题中写有“联网”“最新”，搜索网关也不会被调用。
3. **外部搜索是补充而非替代。** 课程证据足够时默认不搜索；进入混合分支后也同时保留课程
   来源，避免最新网页内容静默覆盖教材口径。
4. **失败降级取决于证据资格。** 只有已经通过 Reranker 与内容角色安全门的课程证据才能支撑
   降级答案，不能因外部服务失败而降低第三周建立的证据门槛。
5. **冲突展示采用“模型识别、服务端约束”。** 语义冲突交给生成模型判断，但一旦声明存在
   差异，服务端强制检查“资料差异”段和双方引用，防止只给结论不展示依据。
6. **诊断信息进入持久化快照。** 历史回答不重新运行搜索；刷新后展示当时的决定、来源与失败
   状态，保证验收结果可追溯。

### 问题及处理

#### “混合模式”容易被误解为每次都搜索

产品目标是允许外部补充，而不是固定串行调用 Web Search。实现将课程覆盖、显式联网意图和
时效性拆成条件，并把判断原因显示给用户；因此同一个“课程资料 + 外部补充”设置下，课程内
问题可以完全不联网，资料缺口或最新信息问题才联网。

#### 外部搜索失败不能与“无资料”混为一谈

HTTP 503、超时、没有合格来源和根本未请求搜索具有不同语义。状态模型保留这些区别，状态图
再结合课程证据决定降级或拒答，避免上游短暂故障被错误显示成课程知识库缺失。

#### 双命名空间引用增加了校验分支

模型可能继续输出旧 `[n]`，也可能引用未采用的搜索结果。生成服务集中解析两类标记、检查
边界并按正文重建引用清单；前端只消费已校验结果，不自行猜测来源类型。

#### 来源冲突不能只靠固定关键词判断

课程与当前官方资料的差异可能以多种方式表达，纯规则无法可靠识别。当前由模型返回冲突声明，
服务端只验证展示形式和引用完整性；该边界被明确记录，后续可用冲突评测集继续增强。

### 当日目标

解决的不是“再增加几类总结模板”，而是总结系统如何理解任意方向的问题。计划日 4 将路由器、
总结 Planner、分节检索、受约束生成和质量校验拆开：用户给出明确方向时，系统围绕该方向生成
专属结构；请求模糊时才采用稳定的综合总结。完成这一基础后，出题分支才能复用相同的“规划—
取证—生成—校验”模式，而不继承固定八段契约。

### 实施目标

- 从根本上移除“所有总结都填充固定八段栏目”的生成方式；
- 不建立持续膨胀的总结意图枚举表，而是从用户原始要求中动态提取总结目标、关注方向、受众、
  详细程度、组织方式、必须包含项和排除项；
- 继续保持总结仅使用课程资料、`[课n]` 引用校验、自动路由和历史会话兼容；
- 本阶段完成并验收后，再在同一请求路由中接入出题分支，避免连续重构路由与生成契约。

### 计划实施顺序

1. **动态总结规划**：新增受 Pydantic 约束的 `SummaryPlan`。路由器只判断是否为总结任务，
   Planner 负责解析范围、目标、开放式关注方向、受众、粒度、篇幅、输出形式、包含/排除条件，
   并生成数量和标题均可变化的章节计划；不把关注方向限制为预置三选一或有限枚举。
2. **固定外壳、动态正文**：将当前固定八字段结果改为稳定元数据加动态 `sections[]`；每个章节
   至少包含标题、写作目的、正文和采用的课程证据编号。只有“总结第三章”一类模糊请求才回退
   到默认综合结构，明确请求不得为了凑模板强行加入无关栏目。
3. **按章节定向检索**：Planner 为各章节生成独立检索目标和查询，不再让所有栏目只共享一次
   通用 Top 12。检索结果仍经过现有 Reranker 与内容角色安全门；证据不足的章节明确提示限制，
   不使用模型记忆补齐。
4. **受约束的分段生成**：生成器严格按计划逐节组织内容，允许提纲、对比、流程、清单、问答等
   Markdown 结构；代码和公式仅在用户明确要求或课程证据确有必要时出现。
5. **去同质化与质量校验**：服务端检查用户要求覆盖率、各章节证据覆盖、`[课n]` 越界/模糊/
   外部引用、未请求的通用内容以及章节间重复度。覆盖不足或重复度过高时只重写问题章节，并为
   重试设置上限；不能修复时返回具体限制，不返回伪合格总结。
6. **交互与持久化**：前端继续复用课程对话输入框，按动态章节渲染；会话快照保存总结计划摘要、
   实际章节和校验诊断，Day 3 的固定结构历史消息仍能正常打开。
7. **测试与文档**：补充 Planner、动态结构、定向检索、引用安全、重复校验、失败降级、历史兼容
   的单元与 API 测试，并在完成时新增计划日 4 验收文档。

### 关键设计与决策

1. **总结意图保持开放字段。** Planner 可以提取“从工程取舍角度总结”“只整理反直觉结论”等
   未预注册方向，不把目标限制为知识点、考点、代码等有限枚举。
2. **结构稳定性放在外壳而非栏目。** API 保留任务类型、范围、诊断和 `sections[]`，章节标题、
   数量、目的和组织形式按请求变化；前端因而无需为每一种新方向增加组件分支。
3. **规划不能代替证据。** Planner 负责决定应写什么，课程检索负责证明能写什么；某个章节
   找不到材料时显示局部限制，不能用模型记忆补齐计划中的空白。
4. **各章节拥有独立检索目标。** 一次通用 Top 12 容易让所有总结依赖相同片段并趋于同质，
   因此计划中的章节分别检索、重排，再由服务端统一编号和去重。
5. **质量校验关注需求覆盖与重复，而不只检查 JSON。** Pydantic 只能保证字段存在，无法证明
   回答真正围绕用户方向；计划增加包含/排除约束覆盖和章节间重复检查。
6. **局部修复优先。** 单节证据不足、遗漏约束或重复过高时只重写问题章节并限制次数，避免
   全文重生成导致原本合格内容和引用漂移。
7. **继续坚持课程证据硬边界。** 动态结构不会放宽 `course_only`、`[课n]` 或 Web Search
   隔离；“更灵活”只指总结目标和表达结构，不指事实来源。

### 风险、边界与处理原则

#### Planner 输出合法但理解错误

结构化输出只能证明字段格式正确。实现时还需把用户原句、必须包含项和排除项保留到校验阶段，
并检查每项是否落入至少一个章节；否则“合法 JSON”仍可能生成错误方向的总结。

#### 分章节检索导致延迟与重复证据增加

每节单独检索能改善针对性，但不能无限增加检索与生成调用。实现时限制章节数、复用本地检索
组件、合并重复 Chunk，并优先采用一次规划、若干本地检索和一次结构化生成；只有失败章节才
产生有限重试。

#### 动态结构破坏历史消息展示

Day 3 已保存固定八段 Markdown，不能要求用户重建会话。前端和快照解析会同时支持旧正文与新
`sections[]`；本计划不通过回写数据库来“升级”旧消息。

#### 过度追求差异造成内容失真

去同质化不是要求每次使用花哨版式。模糊请求仍应稳定、相似课程证据仍可能产生部分相同结论；
验收关注的是用户明确方向是否改变章节和重点，而不是机械规定标题必须完全不同。

### 实际完成内容

- `DynamicSummaryPlanner` 对明确请求执行一次 JSON 规划，动态输出 1～8 个章节；`focuses`、
  `must_include` 和 `must_exclude` 均为开放文本。对“总结第三章”一类模糊请求不调用 Planner，
  使用稳定五节综合计划；
- `SummaryPlan`、`SummarySectionPlan`、`SummaryPlanRead` 和 `SummaryQualityDiagnostics` 均由
  Pydantic 校验，章节 key、文本长度、证据预算和数量有明确上限；
- API 按章节分别调用现有 `answer_search`，继续经过 Reranker 和内容角色门。相同 Chunk 统一
  去重编号，保留各节可用编号集合，最多合并 30 条证据；
- 生成结果改为动态 `sections[]`，服务端要求 key 和标题与计划一致，并校验每节正文引用、声明
  编号和全局编号。分节召回编号是生成偏好；同一范围内的合格课程证据可跨节复用并记录诊断；
- 校验器检查必须覆盖项、明确排除项以及去引用后二元组 Jaccard 重复度。阈值暂定 `0.76`，
  问题章节最多局部重写一次；仍不合格则抛出可诊断错误，不保存伪合格总结；
- retrieval 快照新增计划摘要和质量诊断，继续复用 JSON 字段而不迁移数据库；历史消息缺少新
  字段时前端仍按原 Markdown 展示；
- 前端状态卡显示综合/动态计划、目标、章节数、格式、证据覆盖与局部修复数量；正文继续使用
  现有 Markdown 渲染和引用卡；
- 自动路由增加“请从……角度对比总结……”一类嵌入式总结指令，避免开放表达落回普通问答。

### 第二轮用户验收失败与修复

用户继续测试第 4 条 `从 C++ 实现角度总结二叉树遍历，重点说明函数结构和容易写错的边界。`，
服务端返回“容易写错的边界条件汇总的正文引用与声明不一致”，计划日 4 再次验收不通过。
排查显示生成 JSON 中正文 `[课n]` 与同节 `used_source_ids` 不一致。后者完全可以由正文推导，
不应成为独立真相来源；同理，章节标题和目的已经由 Planner 确定，也不应依赖模型再次精确复述。

修复后，服务端先严格校验正文中的 `[课n]` 是否存在、是否越界、是否混入 `[外n]` 或 `[n]`，
随后从正文重新计算 `used_source_ids`，并用 Planner 值归一化标题和目的。校正章节分别写入
`normalized_source_declarations` 与 `normalized_section_metadata` 诊断，前端显示校正数量。
章节 key、正文引用、范围、包含/排除要求和重复度仍是硬约束。测试使用用户相同原句、相同
“容易写错的边界条件汇总”标题和故意不一致的声明完成 API 回归。
