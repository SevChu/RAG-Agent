#### 100 条数据与候选答案

- split 为 60 train / 20 validation / 20 test；
- 章节族分别为线性结构/树/查找、排序、图；同一分区不得跨 split；
- 覆盖 25 普通问答、10 拒答、15 混合来源、10 总结、10 组卷、20 多轮和 10 隔离；
- 全部 100 条预填候选答案、关键得分点和资料定位，状态为 `candidate`；
- 候选答案不会进入被测模型提示，用户审核后才转换为正式人工标注。

#### 可恢复执行

- 新增逐样本原子结果文件和不可变 run identity；
- 已完成用例永不自动重跑，失败用例需显式 `--rerun-failed`；
- 复用第四周的 `TokenBudgetLedger` 和预算网关，每个调用前持久化保守扣额；
- 正式问答 API 是唯一执行入口，每个用例使用临时课程对话，完成后删除；
- 保存完整本地回答供人工审核，同时生成不依赖 Judge 的确定性报告。

#### 指标与复核

- 确定性指标包括状态、任务路由、范围、引用要求、外部搜索、组卷结构、来源目标
  Recall/MRR、拒答、禁止来源、关键点词项、延迟和 token；
- `human_review` 与 `llm_judge` 为两个独立顶层结果；
- Judge 文件必须记录模型和提示版本，人工 verified 结果保持权威，不允许被 Judge 覆盖。

### 问题、原因与处理

#### Windows pytest 临时目录权限

首次针对性测试因系统 Temp 和旧 `.pytest_cache` 所有权不一致，4 个 `tmp_path` fixture 无法创建。
将 `TEMP/TMP` 指向工作区 `tmp/` 并关闭 cacheprovider 后，同一组测试 10 项全部通过；全量测试也
沿用该隔离临时目录。代码本身没有测试失败。

#### 真实调用的外部数据边界

14 条试点命令在进程启动前被审批层拒绝，因此没有向 DeepSeek 发送请求，也没有读取 API Key、
建立 token 账本或产生计费。原因是用户虽批准“真实数据授权”，但尚未明确同意将问题与检索到的
教材片段发送至 `https://api.deepseek.com`。本轮没有绕过限制；完成所有离线工作后，将该单一
授权项交回用户确认。
