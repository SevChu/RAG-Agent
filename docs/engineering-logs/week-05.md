## 方向调整与历史继承

第 5 周最初曾在 2026-08-10 完成一版“本地 100 条候选集 + M0 冻结基线 + token
预算”的评测基础设施方案。随后产品定位与研究路径发生调整：项目不再局限于学习场景，优先
转为通用智能体；自建标准集延期，先通过公开数据集建立可复现的经典基线。

因此，本周正式执行路线改为：

1. 先完成通用智能体的界面语义和产品文档迁移；
2. 每个公开数据集经过用户逐项审批后，才允许下载和运行；
3. 依次建立检索、幻觉检测和端到端 RAG 评分三类基线；
4. 最后冻结统一默认方案，为后续评分算法改进和微调界面提供可比较起点。

原始方案没有删除，仍作为历史设计分支保存在
[第五周评测基础设施历史日志](./week-05-evaluation-infrastructure.md) 和
[原始计划](../deliverables/week-05-original-plan.md) 中。原方案的本地评测适配层、预算控制、
结果存储和“外发前审批”原则继续沿用；其中 M0 指标只证明链路可运行，不作为公开
Benchmark 的质量结论。

## 本周确认约束

- 对外定位改为“较为通用、回答质量较高的 Agent”，学习场景只是可支持的应用之一；
- 用户可见语义迁移到“资料空间”“智能体对话”，但本周不做数据库表名、API 路径和
  `course_id` 的破坏性迁移；
- Qwen、Kimi、GLM 只预留 OpenAI-compatible 接口，未提供 Key 前不得发起真实请求；
- FiQA、RAGTruth、RAGBench 必须分别审批，前一阶段验收不自动授权下一数据集；
- 原始语料、逐条预测、缓存、模型权重和可能受限的数据不得进入 Git；
- 测试集只用于最终评估，不允许根据测试集反复调参；
- 本周先复现经典算法和建立 Benchmark，算法创新与微调训练留到后续研发周；
- 最终仍需建设项目自有金标准集，公开数据集不能永久替代该目标。

## 本周目标

1. 完成通用智能体产品定位、界面文案和多模型接口的第一阶段迁移；
2. 接入并冻结一个规模合适的标准检索数据集；
3. 在同一协议下跑通 BM25、Dense、RRF 和重排经典检索基线；
4. 分阶段接入 RAGTruth 与 RAGBench，建立幻觉检测和 RAG 评分基线；
5. 冻结每类任务的默认基线、结果格式、复现信息和研究优先级；
6. 发布不含原始数据和逐条预测的脱敏聚合 Benchmark 结果。

### 关键设计决策

1. **先迁移用户语义，再迁移内部模型。** 这样可以快速完成产品定位，同时避免数据库、
   路由和历史数据一起发生高风险变化。
2. **供应商按模型白名单路由。** 用户后续只需填写对应 URL、Key 和模型 ID，运行时无需
   再改业务代码。
3. **未配置即不可选。** 预留接口不等于伪装成可用功能，界面必须明确显示配置状态。
4. **搜索能力单独建模。** OpenAI-compatible 只代表请求协议相似，不代表各供应商都具备
   相同的搜索插件或参数。

## 计划日 3：FiQA 经典检索基线

### 基本信息

| 项目 | 内容 |
|---|---|
| 实施时间 | 2026-08-25 ～ 2026-08-26，FiQA 冻结后执行 |

| 固定测试协议 | 648 queries / 1,706 qrels / top-100 / seed 42 |
| 外部模型 API | 0 次 |
| 本地模型 | BGE-M3、BGE-reranker-v2-m3 |

### 当日目标

- 在同一 FiQA test 协议下复现经典稀疏、稠密、融合与重排方案；
- 记录质量、延迟、缓存大小和输出哈希，形成后续算法改进的可比较基线；
- 选出当前默认检索方案，但不把单次结果包装成算法创新。

### 当日明确不做

- 不根据 test 指标反复调参；
- 不调用外部付费模型；
- 不把本地 embedding、reranker 权重、语料缓存或 TREC 逐条 run 提交到 Git；
- 不把 FiQA 的结果外推为所有领域的通用质量结论。

### 实际完成内容

#### 1. 固定实验协议

- BM25：`k1=1.2`、`b=0.75`；
- Dense：BGE-M3、1024 维、精确余弦检索；
- RRF：`k=60`，BM25 与 Dense 等权融合；
- Reranker：BGE-reranker-v2-m3，最大输入长度 512；
- 所有方法返回 top-100，并用同一查询顺序、同一 qrels 和固定 seed 42；
- 输出 TREC run、结构化指标、阶段耗时、缓存清单和 SHA-256。

#### 2. 可恢复执行与本地缓存

- Dense 语料向量按固定清单缓存，避免每次从头编码 57,638 篇语料；
- 38 条官方空正文生成确定性零向量，不修改原始数据；
- runner 支持从已完成阶段恢复，长耗时任务中断后不需要重跑前序阶段；
- 对输出 run 和缓存计算哈希，保证后续复核能识别内容变化。

#### 3. 经典基线结果

| 方法 | nDCG@10 | Recall@100 | MRR@10 | MAP@100 |
|---|---:|---:|---:|---:|
| BM25 | 0.2309 | 0.4976 | 0.2871 | 0.1855 |
| Dense BGE-M3 | 0.4126 | 0.7188 | 0.5039 | 0.3538 |
| BM25 + Dense RRF | 0.3523 | 0.6993 | 0.4316 | 0.2959 |
| RRF + BGE reranker | **0.4299** | 0.6993 | **0.5162** | **0.3682** |

结果表明：Dense 是当前最强召回方案；等权 RRF 没有带来互补收益，反而低于 Dense；重排可
改善排序质量，但不能召回候选集中不存在的相关文档。

### 关键设计决策

1. **Dense 作为默认召回。** 它在 Recall@100、nDCG、MRR 和 MAP 上全面超过 BM25。
2. **不默认启用等权 RRF。** 经典方法必须接受实测结果，不能因为“融合通常有效”就忽略本次退化。
3. **重排只作用于既有候选。** 默认质量上限受 Dense/RRF 召回集合约束，后续优先探索
   Dense top-100 直接重排。
4. **同时记录质量与成本。** Reranker 约增加 705 ms/query，后续必须用增益/延迟共同判断。

#### 2. 统一评测分类

- RAG scoring：adherence 分类与 relevance/utilization/completeness 排序相关；
- Efficiency：首次耗时、缓存复跑、单查询耗时、缓存体积；
- Reproducibility：数据 revision、参数、seed、输出哈希和环境版本。

1. **Dense top-100 直接重排**：移除本周表现较弱的等权 RRF，验证更纯粹的召回—重排链；
2. **Relevant → Utilized 两阶段完整性评分**：先判断可用证据，再检查答案利用比例，针对
   RAGBench completeness 0.3967 的主要短板；
3. **NLI/句级 span 评分**：用方向性蕴含替代单纯相似度，降低 RAGTruth Dense 假阳性并改善定位。

### 关键设计决策

1. **默认方案是研究起点，不是永恒赢家。** 后续任何改进都必须相对同一冻结协议比较。
2. **公开结果可参考但不可反推样本。** 聚合指标与复现元数据进入 Git，受限内容继续本地保存。
3. **先修最弱环节。** P0 优先覆盖检索融合退化、幻觉 span 定位和完整性评分三处明确短板。
4. **自建金标准集延期但不取消。** 公开 Benchmark 解决短期可复现性，自有 sealed test 负责长期产品质量。

## 已知问题与技术债务

1. **内部领域命名仍偏学习场景。** `Course`、`course_id`、部分文件名和 API 路径尚未迁移；
   需要在有数据迁移与兼容测试的独立版本中处理。
2. **多供应商真实连通性未全部验证。** Qwen、Kimi、GLM 当时没有 Key；当前结论只覆盖
   配置、路由、状态和错误处理，不等于所有模型已实测。
3. **FiQA 融合策略退化。** 等权 RRF 低于 Dense，需要只在 train/dev 上研究加权或直接重排。
4. **RAGTruth span 定位较弱。** 最佳 character F1 仅 0.1777，需要句级切分、NLI 或专门模型。
5. **RAGBench 完整性相关性不足。** 最佳 Spearman 0.3967，是综合评分算法的第一优先级。
6. **公开 Benchmark 不能代表产品全部质量。** 数据域、类别分布和任务形式有限，仍需自建 sealed
   gold set。
7. **历史格式债务未清零。** 4B 收口时全仓仍有 53 个历史 formatter mismatch，未与功能改动混修。
8. **模型与数据许可需持续维护。** 上游 revision、模型卡或数据许可变化时，应更新
   `THIRD_PARTY_NOTICES.md`，不能把第三方资产纳入 Agentic 原创版权。
