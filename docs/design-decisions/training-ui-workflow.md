## 入口与使用顺序

科研侧栏“微调实验室”进入 `/training/datasets`；智能体管理中启用智能体的“模拟微调”进入 `/training/new?agent=<id>`，自动读取当前版本。

1. 创建数据集，填写来源、许可、用途与隐私复核说明，上传 UTF-8 JSONL 或粘贴样本。字段示例可在页面展开；只接受 train / validation。
2. 先校验，再登记不可覆盖的新版本。填写审核人和意见，提交审核后批准；未满足基础条件不能批准。审核历史和撤销保留记录。
3. 创建任务依次选择智能体、已审核数据版本、模拟目标、LoRA/QLoRA 参数，再复核提交。目标由所选数据契约决定，训练基础模型与智能体对话模型分别展示。
4. `/training/runs` 查看记录，`/training/runs/:runId` 查看进度、事件、错误及冻结来源；取消在检查点生效，失败/中断/取消后的显式重试会产生新任务。
5. `/training/adapters` 和详情展示文件完整性、参数、哈希及前驱来源链；归档保留历史。所有产物均为模拟 manifest，没有模型权重或部署入口。

## 版本与错误恢复

复核和提交前重新读取智能体、数据审核和资格。新增可选 `expected_agent_revision_id` 由 UI 始终提交，后端在创建写事务中核对；并发版本变化返回 409，防止在用户确认之后静默固定另一个版本。旧 API 调用方省略此字段仍保留原有“固定创建时版本”语义，无新迁移。

提交中禁用表单和按钮；同一页面、同一请求内容复用幂等键。请求已提交但响应丢失时，输入和键保留，重试返回原任务。表单/幂等键不跨刷新持久化，浏览器刷新后可从任务记录找回已创建任务。

版本停用/更新或审核撤销会退回相应选择步骤，保留其他参数；使用“重新读取所选版本”或重新选择后复核。审核提交使用行版本控制，冲突显示错误并要求刷新版本，保留审核说明。网络错误不清空已填写内容。

选择和分页请求采用递增票据，旧响应及离页响应不覆盖当前内容。任务操作使用独立路由票据，迟到错误不进入新任务页；归档确认返回时页面已变化则不执行旧产物归档。任务列表每 3 秒串行轮询，详情每 900 ms 读取状态和增量事件，终态停止；网络恢复继续读取，离页清除定时器。列表每页 20 条，事件每页 100 条。

真实 GPU 显存、耗时与成本显示“待评估”。后台是否启用来自服务端配置，页面不修改开关，也不能证明 worker 实际健康。默认关闭时任务会排队。运行资格和产物有效性由后端再次判定，前端筛选不替代服务端校验。

edition 通过原智能体 options 获取并缓存；产品版隐藏侧栏和智能体按钮。直接输入训练 URL 显示科研版说明，不挂载子页面或读取训练数据。完整仓库的 product API 返回 403；实际产品源码包不含 Python training 模块，训练路由不存在。共同前端仍可包含界面代码，双版能力分离不等于源码保密。

## 浏览器验收复现

使用仓库已有 Python、Node、Playwright 和已安装 Chromium。测试服务器会拒绝复用已有数据库，不读取 `.env`，只在仓库 tmp 下创建全新合成环境，后台与浏览器连接均限本机。无需正式库、已有资料或模型。以下是本地复现说明，不是正式上线命令。

1. 在仓库根目录为本次选择全新目录名，例如 PowerShell 设置 `$env:AGENTIC_TRAINING_UI_DIR='week08-ui-local-001'`。两个服务器进程都继承该值；用隐藏进程分别运行 `backend/.venv/Scripts/python.exe frontend/e2e/training-server.py research` 和末尾为 `product` 的命令。科研后端端口 18084、产品后端 18085。启动后确认 `/api/health` 的 environment 为 `week08-day04-isolated`。
2. 分别在 frontend 目录，以进程环境 `VITE_API_BASE_URL=http://127.0.0.1:18084/api` / `http://127.0.0.1:18085/api` 启动现有 Vite，使用 `--host 127.0.0.1 --port 15174 --strictPort` / `15175`。无需修改任何 `.env` 文件。
3. 在设有同一 `AGENTIC_TRAINING_UI_DIR` 的终端，依次运行 `node frontend/e2e/training.cjs`、`node frontend/e2e/training-boundaries.cjs`。前者 9 组、后者 4 组；后者依赖前者已完成。每次完整复现使用新的目录名。截图和 JSON 证据写入该 tmp 目录。
4. 测试失败后先检查是否存在未完成任务，必要时通过合成页面取消。正常结束后在该目录的 research、product 子目录各创建一个 `stop` 空文件，服务器优雅退出并释放租约。确认 shutdown 完成后，仅关闭本次 Vite PID；保留证据，不清理其他目录。

测试服务器里的 seed=13 仅在首次执行时注入失败，专用于验证重试；正式 API 不接受故障注入字段。空智能体列表通过浏览器响应替身验证；核心登记/审核、任务、worker、产物和产品边界都连接实际隔离后端。截图临时隐藏既有 Vue DevTools 浮层，不改应用样式。
