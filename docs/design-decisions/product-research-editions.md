# 产品版与研发/科研版分离

用户于 2026-09-10 要求普通智能体全流程不需要 Benchmark，只在科研用途准备评测集。
2026-09-11 从额度中断处继续收尾。同一业务核心提供两种源码发行包，不复制两套应用或数据库。

## 分离边界

| 层 | 产品版 | 研发/科研版 |
|---|---|---|
| 运行模式 | product，源码默认 | research，显式启用；科研包默认 |
| 智能体/资料/生成 | 完整保留 | 同一核心 |
| 表单研究记录 | 隐藏 | 显示，说明仅关联、不代表已通过评测 |
| 模型选项/保存配置 | 不加载研究注册表 | 有研究引用时校验冻结配置 |
| app/evaluation、研究脚本、聚合 Benchmark | 从源码包排除 | 包含 |
| 后端依赖 | 默认运行依赖 | 额外 research 组 |
| 原始评测数据/NLI 权重 | 不需要、不附带 | 按实验需要另行准备，不自动下载 |
| 业务数据/密钥/索引 | 不附带 | 不附带 |

AGENTIC_EDITION 是功能模式，不等于 APP_ENV。发行能力写入 app/core/distribution.py；
产品包 RESEARCH_AVAILABLE=false，设置 research 会明确报错。完整源码保留研究能力但
默认仍为 product。该标记不是授权或多租户安全机制。

## 解耦与兼容

agents/validation 的研究类型仅用于类型检查，注册表加载延迟到显式科研调用。
产品 options 返回 edition=product 和空 evaluation_profiles；模型选项无需研究文件。
产品禁止新建/新增研究引用；已有引用可原样保留或清空，修改运行参数、启停、恢复和生成
不受研究依赖失效影响。复制到新产品智能体时省去研究引用。原配置 JSON 与哈希不被重写。

这是保留历史兼容字段，不是让产品用户配置 Benchmark。版本快照仍固定原绑定，旧研究
结果不会自动变成该智能体或客户部署的评测成绩。客户评测套件与完整运行适用性机制另行设计。

## 依赖和分发

PyArrow 与研究显式使用的 scikit-learn 约束归入 research 依赖组。scikit-learn 同时是
sentence-transformers 的共享传递依赖，产品仍需要它。锁文件记录全部可选组，169 个包
的版本/来源未变；产品默认依赖树没有 PyArrow。安装脚本不下载评测集或清理本机研究数据。

scripts/build_editions.py 按源码目录白名单构建两份 ZIP；排除缓存、数据库、数据集、模型、
本地环境文件与输出，拒绝符号链接和 Windows junction。包内声明发行能力、应用版本和逐文件
哈希；源码包不带 venv/node_modules/dist。分发二进制/离线依赖时仍须按 CONTRIBUTING
重新核对实际 SBOM 和许可清单。科研包也不打包原始数据，本机研究资产全部保留。

## 安装入口

- [产品版说明](../editions/product.md)：uv sync --frozen --no-dev。
- [科研版说明](../editions/research.md)：再添加 --group research；开发测试时保留 dev 组。
- 两版启动均使用 uv run --no-sync，避免启动时隐式重新选择依赖组。
- 两版共享 20260910_06 迁移链；本次分离没有新 schema 或业务数据库修改。

## 验证方法

scripts/verify_product_edition.py 使用实际解压的产品包启动应用，并禁止 app.evaluation
与 PyArrow 导入，再运行资料、上传、四类生成、会话和删除回归。前端分别验证产品隐藏
研究控件、科研显示用途边界并可保存研究关联。另核对依赖树、包内容与逐文件 SHA-256。

## 2026-09-11：仓库与开发者配置

采用现有单仓库、同一版本/Tag、两个源码发行包。修复、业务核心与迁移共用，避免维护
两套分叉。完整仓库始终包含科研源码；若未来需要按团队/许可证限制科研源码访问，再单独
设计仓库或模块权限，不把当前产品模式当作保密边界。

本机开发者要求保留全部已实现的科研能力，通过忽略的 .env 设置 research，科研依赖
和既有资产保留；共享默认与产品包仍为 product。该选择不提高 OS 权限或绕过应用约束。
