# 动态总结规划设计决策

## 状态

- 决策日期：2026-08-04
- 计划实施：第 4 周计划日 4
- 当前状态：已实施，并于 2026-08-06 通过用户验收
- 前置条件：计划日 3 自动路由与课程总结已完成并通过验收

## 问题

计划日 3 使用固定八段结构生成所有课程总结。该结构能够保证基本完整性，但用户请求“总结
知识要点”和“总结考试重点”时，结果的版式和内容权重仍然接近。问题并不只涉及这两种表达：
用户还可能要求按代码实现、概念对比、算法流程、反例、章节联系、特定受众或自定义方向总结。

如果继续枚举意图并为每种意图增加固定模板，规则数量会持续增长，组合请求和未登记的新方向
仍然无法正确处理。因此不采用“增加若干总结类型”的修补方案。

## 决策

采用“动态总结规划 → 分节定向检索 → 受约束生成 → 覆盖与重复校验”的流程。请求路由只判断
问答、总结或后续出题等顶层任务；总结内部不依赖有限的方向枚举。

### 动态计划契约

`SummaryPlan` 至少表达：

- 课程、文档、章节或知识点范围；
- 用户的总结目标和开放式关注方向；
- 受众、详细程度、篇幅和期望组织方式；
- 必须包含与明确排除的内容；
- 动态章节列表，以及每节的目的、检索目标和证据预算。

关注方向以受长度约束的文本或字符串列表保存，不使用只能覆盖已知需求的业务枚举。输出形式可以
使用受控的展示方式集合，但不能反过来限制用户想总结的内容。

### 动态结果契约

总结结果保留稳定外壳，例如标题、范围、目标、动态 `sections[]`、可选复习建议和已采用证据
编号。正文不再要求同时出现八个固定栏目。每个章节至少包含标题、目的、内容和课程证据编号，
由 Pydantic 校验结构、数量和长度。

Planner 已确定的章节标题、目的，以及可从正文 `[课n]` 推导的 `used_source_ids` 都属于冗余
生成字段。模型返回不一致时，服务端使用计划和正文自动归一化并记录诊断，不得因辅助字段漂移
拒绝一份引用本身合法的总结；章节 key、正文、引用范围和用户约束仍执行硬校验。

### 证据与生成

- 每个计划章节拥有自己的检索查询，避免所有方向复用同一组通用证据；
- 分节召回结果是该节的优先证据集合，不是安全授权边界。同一次总结中已通过课程、文档或章节
  范围过滤的合格课程证据可以跨节复用；服务端记录复用诊断，但不得因此误报为非法引用；
- 检索结果继续通过 Reranker 和内容角色安全门；
- 总结继续强制 `course_only`，禁止 Web Search、模型记忆和 `[外n]`；
- 生成器按计划逐节生成，证据不足时说明具体章节的限制，不臆造内容；
- 用户请求模糊时使用默认综合计划，明确请求优先遵循用户目标，不强行补齐通用栏目。

真实模型验证后增加以下执行边界：明确请求最多 4 节，模糊综合请求固定 5 节；分节结果按 rank
轮询合并，最多保留 10 条、8000 字符证据。Planner 与总结 JSON 均执行字段归一化，无法解析时
各紧凑重试一次。JSON 模式客户端统一附加小写 `json`，以兼容上游 `response_format` 校验。

### 后验校验

结果至少校验：

1. 用户每项明确要求是否在计划和正文中得到覆盖；字面匹配只能生成 warning，不能把可能的
   同义表达误判为硬失败；
2. 明确排除的内容是否被错误加入；
3. 各章节是否有合格课程证据；
4. 引用是否缺失、模糊、越界或混入外部编号；课程专用总结中的合法 `[n]` 先升级为 `[课n]`
   再校验，`[外n]` 和越界编号仍硬拦截；
5. 章节间是否存在过高的文本或语义重复；
6. 正文是否实质遵循章节目的，而非只修改标题。

失败时优先局部重写存在问题的章节并限制重试次数。重试后仍不合格，则返回可诊断的限制信息，
不得把失败结果作为完成的总结持久化。

无引用章节不进入局部重写：服务端直接丢弃其无依据正文并标记资料不足。如果整份结果均无有效
引用，则以正常 `insufficient_evidence` 响应收口，而不是暴露结构化生成错误或保留模型常识。

## 向后兼容

- 课程助手保持同一个对话输入框和自动路由，不要求用户选择总结类型；
- Day 3 已保存的固定八段总结继续按原快照展示；
- 新快照增加计划摘要、动态章节和质量诊断时优先复用 JSON 字段，除非实施时确认必须迁移；
- 普通问答的混合来源、搜索降级和引用规则不因总结改造而改变。

## 与出题的关系

动态总结规划是计划日 4 的第一优先级和出题接入前置完成门。它通过验收后，出题可以复用
“先规划、再检索、再生成、最后校验”的模式，但总结仍只使用课程资料，出题则遵守已确认的
课程改编题最多 30%、外部补充题最多 20% 等独立来源配额。

## 验收原则

验收不能只比较“知识要点”和“考试重点”两个样本。至少用 8 个不同方向、组合约束、排除约束
和一个未预注册方向验证输出的结构与重点确实随请求变化，同时验证模糊请求回退、引用安全、
证据不足、重复度、结构化输出失败和历史兼容路径。
