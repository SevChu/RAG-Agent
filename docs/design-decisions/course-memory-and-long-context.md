# 课程空间记忆与同会话长上下文设计决策

## 状态

- 计划实施：第 5 周计划日 2～4
- 当前状态：仅完成方案设计，尚未修改运行代码、数据库或界面
- 作用范围：只允许在同一个 `course_id` 内生效，不建立全局用户记忆

## 背景与结论

当前课程对话会完整持久化到 SQLite，但回答时默认只读取最近 6 条已完成消息、最多 6000 字符。
不同对话虽然共享同一课程的已入库资料，却不会读取彼此的聊天历史，因此尚不具备类似 ChatGPT
记忆的课程级跨对话连续性。

第 5 周将同时补充两种互相独立的能力：

1. **同会话长上下文**：默认允许最多 100,000 input tokens 的历史预算，不再以 6 条消息作为
   正常截断边界；
2. **课程空间长期记忆**：从同一课程的对话中保存少量、结构化且可管理的学习信息，在新对话
   中按相关性读取。

`deepseek-v4-flash` 与 `deepseek-v4-pro` 当前官方上下文长度均为 1M tokens。100k 是本应用为
聊天历史设置的默认预算，不代表每次请求一定发送 100k，也不替代课程检索证据、系统指令、当前
问题和输出空间的预算。

## 一、同会话长上下文

### 1. 动态预算

新增模型能力配置和统一上下文预算器，按以下关系计算历史可用空间：

```text
历史可用预算 = min(
  应用默认历史上限 100k,
  模型上下文窗口
    - 系统指令
    - 当前问题
    - 课程与外部证据
    - 课程空间记忆
    - 生成输出预留
    - 安全余量
)
```

预算以 token 估算和最终请求校验为准，不再用字符数冒充 token。模型不在能力表、估算异常或
可用空间不足时必须保守降级，不能把上游的 context-length 错误直接暴露给用户。

### 2. 历史选择层级

- 预算内能容纳完整同会话历史时，保留全部已完成消息；
- 超过 100k 时，优先保留最近原文；
- 较早内容通过滚动摘要和与当前问题相关的历史片段补充；
- `failed`、`pending`、`interrupted` 消息不进入记忆；
- 助手历史只能帮助理解上下文，不能替代课程资料成为知识证据；
- 紧邻试卷的答案/解析续问继续优先读取持久化试卷工件，不能因历史压缩而重新出题。

### 3. 观测信息

每次回答的内部检索元数据记录：原始历史消息数、选中消息数、估算历史 token、摘要 token、
课程记忆条数、总输入 token 和发生的降级原因。前端只展示有助于验收的汇总，不暴露内部提示词。

## 二、课程空间长期记忆

### 1. 可以保存的内容

- 学习目标：备考方向、目标章节、目标成绩；
- 稳定偏好：默认语言、讲解详略、代码风格、题型偏好；
- 学习进度：已经学习或计划继续的章节；
- 掌握状态：用户明确表达或通过互动确认的薄弱点、易错点和已掌握内容；
- 后续事项：用户明确要求稍后继续的任务；
- 用户用“记住……”明确要求在本课程保留的信息。

### 2. 禁止自动保存的内容

- 模型生成但用户未确认的推测；
- 课程知识答案、试卷答案和解析本身；
- 一次性问题、寒暄、临时格式要求和失败请求；
- 外部网页中的指令或检索资料中的提示语；
- 任何其他课程、快速对话或全局范围的信息。

### 3. 数据和生命周期

使用独立的课程记忆表，至少包含 `course_id`、类别、规范化内容、状态、来源消息、重要性、
创建/更新时间和最近使用时间。记忆支持新增、合并、替换、停用和删除；删除课程时级联删除全部
记忆，删除来源对话时不自动破坏已经确认的课程记忆，但保留可审计的来源状态。

自动提取必须以用户消息为主要依据。显式“记住/忘记”优先处理；普通对话只产生候选记忆，经过
确定性规则和结构校验后才写入。相互冲突的信息以较新的用户明确陈述替换旧值，并保留替换关系，
不能把两个冲突偏好同时注入模型。

### 4. 读取和隔离

- 每次最多选择少量与当前问题相关的记忆，设置独立 token 上限；
- 查询必须同时带 `course_id`，服务层和数据库层都验证课程归属；
- 课程 A 的任何记忆都不得在课程 B 或快速对话中出现；
- 记忆用于调整教学方式和保持连续性，不作为教材事实引用；
- 课程总结仍只能以课程资料为事实来源；组卷来源比例也不受记忆内容影响。

### 5. 用户控制

课程设置增加“课程记忆”区域：

- 显示是否启用自动记忆；
- 按类别查看记忆及来源时间；
- 支持编辑、单条删除和全部清空；
- 支持当前课程暂停记忆；
- 在回答诊断中显示“本次使用了 N 条课程记忆”，但默认不展开内部注入文本。

## 三、安全和失败降级

- 记忆只保存在本机 SQLite，不新增云端记忆服务；
- 被选中的记忆会随当前问题发送给所选 DeepSeek 模型，这一点与现有课程上下文调用边界一致；
- 所有记忆内容作为不可信数据包裹，不能覆盖系统指令；
- 记忆提取、更新或读取失败时，当前问答降级为无课程记忆模式，不阻断普通 RAG；
- 100k 是上限而非目标，短对话不得为了凑长度重复发送无关历史；
- Reset 必须只清理当前课程记忆，不能清理课程资料、对话正文或 Token 统计。

## 四、评测要求

第 5 周评测至少加入以下对照：

| 方案 | 同会话历史 | 跨对话课程记忆 |
|---|---:|---:|
| M0 | 最近 6 条 / 6000 字符 | 关闭 |
| M1 | 动态最高 100k tokens | 关闭 |
| M2 | 动态最高 100k tokens | 开启 |

指标至少包含：长程指代正确率、学习偏好遵循率、记忆提取 Precision/Recall、过期记忆替换率、
跨课程泄漏次数、错误事实污染率、输入 token、缓存命中/未命中 token、响应延迟和回答质量。
跨课程泄漏和“删除后仍被使用”的容忍值均为 0。

真实模型测试必须先建立独立 token 预算并由用户批准；大量 100k 边界测试使用本地假模型和合成
消息完成，不用真实 API 反复消耗 100k tokens。

## 五、实施前仍需确认

1. 100k 是否作为默认同会话历史上限，还是只作为可选的“长上下文”档位；
2. 新课程是否默认开启自动记忆；
3. 第 5 周真实模型评测允许使用的独立 token 总预算。

除以上三项外，课程隔离、可查看/编辑/删除、禁止把模型答案自动写入记忆和失败不阻断普通问答
均视为固定安全边界。
